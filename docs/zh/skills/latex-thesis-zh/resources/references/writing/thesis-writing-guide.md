# 中文学位论文章节写作主线指南

本指南用于在已有中文 LaTeX 学位论文中做章节级写作优化。它不是英文会议论文 section-writing 的直接翻译；优先服从学位论文的章节结构、模板规范、标题后导语、GB/T 7714 引用和答辩可解释性要求。

## 使用边界

- 用于：绪论、文献综述、方法章节、实验章节、总结与展望、摘要/创新点/结论对齐。
- 不用于：从零代写学位论文、编造文献、编造实验、绕过学校模板要求。
- 默认保留 `\cite{}`、`\ref{}`、`\label{}`、数学环境、参考文献键和模板宏命令。

## 总体主线

一篇学位论文应形成一条可答辩的主线：

```text
研究背景 -> 技术瓶颈/研究空白 -> 科学问题 -> 本文方法/章节工作 -> 实验证据 -> 贡献闭合 -> 局限与展望
```

修改章节时先写出这条主线，再判断每一章是否在推进它，而不是并列堆放多个工作。

## 绪论

推荐结构：

1. 研究背景：说明问题出现的领域语境和应用价值。
2. 技术瓶颈/研究空白：从已有方法或实践限制中推出未解决问题。
3. 科学问题：把空白收束为本文要回答的核心问题。
4. 本文工作：说明方法或系统如何回应该问题。
5. 主要贡献：每条贡献都应能映射到后文方法或实验。
6. 章节安排：说明各章如何递进，而不是机械罗列标题。

检查点：

- 是否从背景直接跳到本文工作，缺少前人不足或技术原因。
- 是否把“研究意义”写成口号，而没有对应的技术瓶颈。
- 是否每条贡献都有实验、分析或章节证据支撑。

> 绪论专章细则（引用配额、年份分布、研究现状可视化、科学问题三要素、四方闭合）
> 见 [introduction-guide-zh.md](introduction-guide-zh.md)；对应脚本检查为
> `analyze_literature.py --intro-citations` 与 `analyze_logic.py --intro-mainline`。

## 正文章引言（一段式 / 两段式，承上启下）

第 2 章到结论前的每一章，章标题之后宜先写一段**章引言**再进入小节，与章末"本章小结"首尾呼应。在位置形态上，无论是**编号引言节**（`\chapter` 后直接 `\section{引言}`）还是**章后导语**（章标题后不编号正文），两者均合规（详见 [method-chapter-guide-zh.md](method-chapter-guide-zh.md) 第三节）；在自然段数上，**一段式与两段式均合规**。paper-to-chapter 工作流下**始终写承上句更稳**（有章间依赖时），更利于盲审定位主线，因此承上句为推荐要件而非写死段数；但它**推荐而非硬性**，弹性边界见下方"弹性口径"（方法章细则见 [method-chapter-guide-zh.md](method-chapter-guide-zh.md) 第三节，两段与一段模板即其引用来源）。

**篇幅**：一般 1~2 个自然段、约 300~500 字（方法文献密集章可扩长、承担小型综述并带 `\cite`）。它不是摘要，也不要重复绪论文献综述里已讲过的内容。

### 共同要件（要件固定、段数灵活）

无论采用一段式还是两段式，合格的正文章引言均应覆盖以下四个核心语义动作（要件固定、段数灵活）：

| 要件 | 作用 | 典型句式 | 必需性 |
| --- | --- | --- | --- |
| ① 问题 | 锚定本章对象的工艺现象或数据特性，推导技术问题及其后果 | "＜对象＞由＜工序＞以＜周期＞获得……＜现象＞导致＜问题＞，影响＜后果＞。" | 必需 |
| ② 承上接口 | 说明与前序章节的衔接，以角色复用句指代前章成果 | "第 3、4 章构建的预测模型作为本章适应度函数……" | 按依赖（并列章可省） |
| ③ 方案宣告 | 宣告本章提出的方法、模型或系统 | "针对该问题，本章提出＜方法名＞（Full Name, ABBR），用于……" | 必需 |
| ④ 收束或路线 | 交代本章研究路线或对全篇/后续的价值收束 | "本章首先……随后……最后验证……" 或 "为第 Y 章提供……支撑" | 必需（二选一或并用，不写节号目录） |

### 两段式

两段式适合承上需要展开说明前章结论与局限（≥ 2 句）、或本章问题与方案包含多层次的场景。两段式第①段亦可写为"现象 → 问题"而非纯承上，承上句可落在第①段末或第②段首（语料观察，已由弹性口径覆盖）。

**两段角色**：

1. **承上（第①段）**：点明前一章对本章的价值——前一章解决了什么、得出什么结论，由此引出本章为何要继续。用**章节号**（"第 2 章"）指代，避免"上一章 / 上文 / 前一章"这类相对表述（便于跳读定位）。
2. **启下（第②段）**：交代本章针对什么问题、核心思想是什么、相对已有方法的优势在哪；段末视学科需要，用一两句**方法路线预告**（"首先……其次……最后，基于……实验验证了……"）或本章各节安排（"本章组织如下：…"，工科常配一张本章框架图）。路标段非硬性要求，可结合学科与导师习惯取舍。

**可套用模板**：

```text
第 X 章……解决了……，并得出……，但在……方面仍存在……。
针对这一问题，本章提出……，其核心思想是……，相比……的优势在于……。
本章组织如下：N.1 节……，N.2 节……，N.3 节……。
```

### 一段式

一段式在单一技术问题、承上可压缩为单句角色复用句、方案一句即可宣告的章节中非常常见且精炼。

**六步推进序**：

| 步 | 要件 | 句数 | 必需 | 写法要点 |
| --- | --- | --- | --- | --- |
| ① 对象锚定 | 问题 | 1~2 | 必需 | 本章对象的工艺现象或数据特性，带具体量（周期、比例、维数）；不重述绪论行业背景 |
| ② 问题推导 | 问题 | 1~3 | 必需 | 由现象推出本章要解决的技术问题及其后果（"导致……影响……"） |
| ③ 必要性句 | — | 0~1 | 可选 | 只有落到本章对象时保留（"为此，亟需……"）；"具有重要意义和学术价值"类空泛句删除（指路 deai） |
| ④ 承上接口 | 承上 | 0~1 | 按依赖 | 角色复用句 + 章节号，可列举（"第 3、4 章的预测模型作为本章适应度函数"）；并列章可省；不用"上一章" |
| ⑤ 方案宣告 | 方案 | 1~2 | 必需 | "针对该问题，本章……构建 / 提出＜方法名＞（English Full Name, ABBR），用于……" |
| ⑥ 收束或路线 | 收束或路线 | 1~3 | 必需 | 价值收束（"为……提供……支撑"）或方法路线（"首先……随后……最后……"），二选一或并用；不写节号目录 |

**一段式模板（合成文本）**：

```text
<对象>由<数据/工序>以<周期/规模>获得，而<关键量>……。<现象>导致<技术问题>，影响<后果>。
[第 X 章的<产出>在<条件>下<局限>。]
针对该问题，本章基于<思想>，构建<方法名>（English Full Name, ABBR），用于<作用>。
本章首先……，随后……，最后基于<数据>验证……；[为第 Y 章的<任务>提供<接口>。]
```

**篇幅与起句**：
- 篇幅：单自然段，约 300~600 字、6~12 句（600 为未标定 / UNVERIFIED 提示阈值）。
- 起句三种写法（引自 W1）：
  1. 开门见山式：直接从本章研究对象与工艺/数据现象切入；
  2. 提问式：以本章拟解决的核心技术矛盾或疑问开篇；
  3. 承上启下式：首句直接交代承前启后的角色复用接口。

**一段式正反例（合成文本）**：
- **合规正例**：
  > 连续流反应过程的在线传感序列通常以秒级频次采集，数据维度高且存在非平稳漂移。采样波动导致瞬态特征难以准确提取，影响产物纯度软测量的响应速度。为此，亟需提高特征提取在非平稳工况下的自适应表征能力。本章将第 2、3 章建立的动态校准模型作为基础特征提取器，针对多工况非平稳漂移问题，提出一种自适应注意力门控网络（Adaptive Attention Gating Network, AAGN）。本章首先给出 AAGN 网络的动态门控拓扑与损失约束，随后设计抗噪更新机制，最后在实测数据集上验证表征性能，为第 5 章闭环优化控制提供高保真状态输入。
  > （分析：对象锚定 → 问题推导 → 必要性 → 承上列举 → 方案宣告 → 路线与收束，要件完整，全段约 270 字（示例为压缩版，实际写作按 300~600 字展开），推进紧凑。）
- **不合规反例**：
  > 随着现代工业化进程的高速发展与智能制造技术的广泛普及，工业大数据软测量在现代流程工业中具有极其重大的战略意义、实用价值与广泛的应用前景，是当前工业界和学术界共同关注的研究焦点与前沿热点课题。对于本章的研究对象而言，由于实际生产过程中受到诸多复杂多变的恶劣现场环境和各类不确定性随机干扰因素的共同严重影响与多重制约，导致现场传感器采集得到的动态数据序列往往不可避免地呈现出高度复杂的非线性、多模态、大滞后和非平稳等恶劣特性，给工业系统的高精度软测量与安全稳定运行控制带来了极大困难和严峻挑战。本章针对上述重大挑战，提出了一种创新型的软测量算法框架。本章安排如下：4.1 节介绍引言；4.2 节介绍相关工作；4.3 节提出算法；4.4 节进行实验；4.5 节总结本章。本章首先设计算法模型，其次进行参数优化，最后进行实验验证。
  > （缺陷分析：① 重述宏观背景与套话意义句，指路 `deai` 空泛表达；② 单句超过 120 字，指路 `check_style_zh.py` E-LONGSENT 超长句；③ "重大挑战/极大困难"词汇堆砌，指路 `academic-style-zh.md`；④ 节号目录与方法路线双写，违反去重原则，指路 [`paragraph-roles-zh.md`](paragraph-roles-zh.md)。）

### 段式选型

| 条件 | 一段式 | 两段式 |
| --- | --- | --- |
| 承上 | 可压成一句角色复用句，或并列章不承上 | 需说明前章结论及其局限（≥ 2 句） |
| 问题层次 | 单一技术问题 | 两层以上问题，或需先立框架再立问题 |
| 方案 | 一句可宣告 | 方案含多个模块需逐一点名 |
| 篇幅 | 约 300~600 字、6~12 句 | 约 400~900 字；文献密集需 `\cite` 小型综述可 ≥ 3 段 |
| 全文一致性 | 各章可混用（语料 2/5 混用），不强求统一 | 同左 |
| 共同禁忌 | 同一引言内不双写节号目录与方法路线；不重述绪论背景与综述 | 同左 |

**弹性口径**（5 篇工业博士论文核实，检查器据此降误报，与 method-chapter-guide-zh.md 第三节一致）：

- **并列方法章可不承上**：承上强度 **∝ 章间真实依赖**。纯并列方法章（各自独立立论、不复用前章产出）引言可不回指前章，检查器对此**只给 Info 推荐、不判缺陷**；仅当章内已复用前章成果（正文出现"第 X 章"）而引言漏掉承接时，才按缺承上提示补角色复用句。
- **角色复用句承接合规**：承接靠"角色复用句"而非"叙述回顾段"——不复述前章做了什么，直接声明"将第 X 章的预测模型作为本章适应度函数"即合规承上。
- **方法路线预告式启下合规**：启下写成"首先……其次……最后"的方法路线预告即可，不必写"N.2 节将介绍……"的节号目录，两态均合规。
- **不重述行业背景与双写目录**：章引言不重述行业背景（与“不重复绪论综述”并列）；目录式与路线式二选一、不在同一引言内双写；节号目录不逐节展开每节内容。各级段落职责与去重规范详见 [`paragraph-roles-zh.md`](paragraph-roles-zh.md)。

**正反例**：

| 写法 | 判定 |
|------|------|
| "第 2 章建立了基线模型，但其在长序列上开销过大。针对这一瓶颈，本章提出稀疏注意力机制……本章组织如下：3.1 节……" | 通过（承上有章节号、启下有问题+思路+路标） |
| 单段内完成对象锚定、问题推导、第 2、3 章模型复用、提出新方法与路线预告（约 400 字） | 通过（一段式：六步要件完整，承上列举章节号，无目录与路线双写） |
| 纯并列方法章：引言只立本章问题、预告本章方法路线，不回指前章 | 通过（并列章可不承上，只 Info 推荐显式承接） |
| 单段引言中既列出"N.1 节……N.2 节……"，又紧接着写"首先……随后……最后" | 瑕疵（目录与路线双写，违反去重原则，应二选一） |
| 章内 N.3 节写"沿用第 X 章的特征集"，但引言完全不提第 X 章 | 缺承上（有依赖线索却漏承接，应补角色复用句） |
| 章标题后直接 `\section` 或公式 | 缺章引言（既缺承上也缺启下） |
| "上一章讨论了基线方法。" 单句即转入小节 | 相对指代 + 过简（应补齐问题、方案与收束或路线要件、改用章节号） |
| 把整章方法细节写进章引言 | 过长（细节应下沉到对应小节） |

> 边界：绪论（第 1 章）按"绪论"一节的漏斗式写法处理，不套用本节两段式；本节只面向正文各章。

## 正文章末小结（单段收束式）

第 2 章到结论前的每一章，章末"本章小结"应与章首引言形成首尾呼应：章引言负责说明"为什么写本章"，本章小结负责说明"本章解决了什么、如何证明、对全篇有什么支撑"。它不是最终"总结与展望"的缩写，也不是把各节标题重新罗列一遍。

**篇幅**：默认写成 **1 个自然段**。学校模板、导师或用户明确要求多段或列点时服从该要求；
不得把单段、固定字数或固定数字个数升级为通用硬规则。序词只用于原文确有时间或执行先后的过程，
不能把并行模块、方法接口或独立验证任务强写成“首先—其次—最后”。

**论证边界**：小结不新增引用、公式、图表或推导（扩展既有“不新增未在原文出现的引用”，详见 [`paragraph-roles-zh.md`](paragraph-roles-zh.md)）；以单分句串方法要点合法，逐步骤复述训练或部署流程不合法；回指本章正文已有图表（`\ref`）合法。

**单段角色顺序**：

1. **问题/目标**：开头点明本章围绕的核心问题、评价对象或技术瓶颈。
2. **工作/方法**：概括本章提出、构建、设计或分析了什么，不展开公式推导细节。
3. **过程/证据**：压缩说明关键步骤、实验对象、案例、指标或验证路径。
4. **结果/价值**：只写原文已有证据能够支撑的结论；缺少数据时标为证据不足，不补造结果。
5. **主线支撑**：收束到本章对后续章节、总体贡献或全文科学问题的支撑作用。

**按章型落实五个角色**：

| 章型 | 工作/方法重点 | 过程/证据重点 | 合法边界 |
| --- | --- | --- | --- |
| 框架/过程章 | 对象、约束、问题推导与总体框架之间的关系 | 流程分析、框架覆盖或后续章节映射；无定量指标也可成立 | 不为凑“结果”虚构 RMSE、显著性或应用效果 |
| 方法章 | 用模块或功能作主语，说明输入、输出和接口；串行或并行关系以正文事实为准 | 每个独立验证目标都要覆盖，联合任务不能只写主任务 | 不用序词代替真实接口，不由完整设置猜单组件贡献 |
| 系统/工程章 | 用运行约束、系统机制或操作任务组织，而不是复述组件和界面 | 区分离线、观察性、试点或运行证据，并保留环境与范围限定 | 只有真实部署时序才使用过程序词，不把观察记录升级为闭环收益 |

小结先列出章内全部独立任务及其证据状态，再压缩成段。某项只有方法说明而没有验证时，可以写
“构建/设计了……”，但不能补成“验证表明”；某项证据缺失时明确标为 `missing evidence`，不能因
另一任务有结果而省略该项或共享其结论。

**可套用模板**：

```text
本章围绕……问题，针对……不足，提出/构建了……。首先，……；其次，……；然后，……；最后，……。以……为实验/案例对象的验证表明，……，从而为后续……/全文……提供了支撑。
```

**正反例**：

| 写法 | 判定 |
|------|------|
| "本章围绕非平稳工业过程运行工况评价中的异常刻画与动态响应不足问题，提出……首先……其次……然后……最后……验证表明……为后续优化调控提供支撑。" | 通过（单段、问题-方法-证据-价值闭合） |
| 连续写三段："本章首先介绍……。本章其次介绍……。本章最后介绍……。" | 过散（应压成一个自然段，避免目录式复述） |
| 用条目列出"1. 完成了…… 2. 完成了…… 3. 完成了……" | 非默认形态（除非模板/导师要求，否则改为连续段落） |
| "本章提出的方法达到国际领先水平，填补国内空白。" 但正文没有对应证据 | 证据越界（应删除或改为可验证表述） |
| 框架章只有流程分析与后续章节映射，没有指标 | 可合法收束框架覆盖和主线支撑，不要求补造数值 |
| 方法章含预测与诊断两个独立任务，小结只写预测结果 | 任务覆盖不全（应补诊断任务的工作与真实证据状态） |
| 系统章按真实“接入—观察—回退”顺序描述，但材料只证明短期观察 | 可保留时序；证据结论须止于短期观察，不得写成生产闭环收益 |

> 边界：最终"结论/总结与展望"应综合全文贡献、局限与未来方向；本章小结只做章内证据收束，不机械重复每章"第 X 章……"句式。

## 文献综述

推荐链条：

```text
共识 -> 分歧 -> 局限 -> 空白 -> 本文切入点
```

每个主题组应先说明该组文献解决了什么，再比较方法假设、机制、适用范围或失败模式，最后指出与本文问题相关的局限。不要按作者年份逐条点名。

边界：

- 不新增未在原文出现的引用。
- 不把“相关研究较少”写成“尚无人研究”，除非已有证据。
- 如果研究空白缺少引用支撑，标为“证据不足”，不要强行写成确定结论。

## 方法章节

> 若第二章为工业/过程背景的**过程分析章式**（工艺流程分析 + 全文方法框架，而非直接写方法），
> 先读 [process-chapter-guide-zh.md](process-chapter-guide-zh.md)，对应脚本检查为
> `analyze_logic.py --process-chapter`；判别为"第二章即方法+实验"流派时才套用下述方法章三问。
>
> 第 3 章起的正文方法+实验章（"一章一方法 + 同章实验"章式）细则见
> [method-chapter-guide-zh.md](method-chapter-guide-zh.md)——五段骨架、章引言承上分级、
> 实验工业版规范、拼接感/草稿态清单；对应脚本为 `analyze_experiment.py --per-chapter`
> 与默认运行的 P-PAPER 拼接表述扫描。

每个核心章节或模块应回答三件事：

1. **动机**：为什么这一章/模块必须存在，它回应了哪个瓶颈。
2. **设计**：输入、处理流程、关键结构、输出是什么。
3. **优势**：相对可比方案有什么技术收益，后文如何验证。

章节之间需要显式递进：

```text
基于上一章提出的 ...，本章进一步解决 ...
```

若多项工作只是并列放置，需要补“共同科学问题”和“递进关系”。

## 实验与讨论

实验章节不应像项目汇报。推荐层次：

1. 实验设置：数据、指标、基线、协议公平性。
2. 有效性：主结果与强基线对比。
3. 消融/敏感性：验证关键模块、参数或设计选择。
4. 机理解释：解释结果原因，而非复述表格。
5. 文献回溯：与文献综述中的代表性工作比较。
6. 局限与启示：说明适用范围和后续改进。

禁止把未报告的数据写成结论。若缺少基线、消融或显著性信息，应明确标记缺口。

## 摘要、创新点与总结

摘要、创新点和结论应像“三方闭合”：

| 位置 | 应回答 |
| --- | --- |
| 摘要 | 研究问题、方法、结果、意义 |
| 创新点/主要贡献 | 本文相对已有工作的增量 |
| 总结与展望 | 已验证的贡献、局限、未来方向 |

检查每条创新点是否在结论中被回应，且是否有实验或章节证据支撑。

> 摘要骨架细则（对象定位首句、痛点段、总起句冒号收束、编号工作段、中英一致性、字数校规）
> 见 [abstract-structure.md](abstract-structure.md) 的「学位论文摘要骨架（thesis 模型）」节，
> 对应脚本 `analyze_abstract.py`（默认 thesis 模式，`--bilingual` 查中英一致性）。
> 结论章细则（扁平三段式、贡献条骨架、展望空话黑名单、结论≠摘要、数值一致性）见
> [conclusion-guide-zh.md](conclusion-guide-zh.md)，对应脚本 `analyze_conclusion.py`。

## 输出建议格式

```latex
% THESIS-WRITING（第 N 行）[Severity: Major] [Priority: P1]: 章节主线断裂
% 问题：绪论提出了“提高鲁棒性”，但实验章节没有对应验证。
% 建议：补充鲁棒性实验，或将绪论贡献改为当前结果能支持的范围。
% 证据状态：needs evidence
```
