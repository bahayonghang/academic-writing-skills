# 中文学位论文单元润色协议

## 适用范围与模式

用户明确要求润色、改写或优化语句时，产出一个自然段或一个 depth-3 小节的完整润色稿。用户只要求检查、审校或看看问题时，只返回诊断，不改写正文。入口与参数见 [polish 模块](../modules/polish.md)。

论证或逻辑问题先交给 [logic](../modules/logic.md)。多轮顺序是论证/逻辑、句子结构、词汇/排版；本协议只处理后两层，不调整段落顺序，不增删论断。既有 `--strength minimal` 只允许词汇、标点和明显语法错，拆合句与语序调整属于 `moderate`；这里不使用 `restructure` 的段落重排能力。编辑轴不传给清单/核对脚本。

## 五步流程

1. 运行 `--plan`，确定一个单元及源文件行区间。清单是当前文本的快照，每次润色前重新生成。只读取当前单元和标出的只读邻域，不整本读取。
2. 在带章节结构的入口文件上运行下列三个单元前诊断，替换章节键，只采纳源文件与行区间落在当前单元内的条目；不要在裸润色片段上运行它们后宣称无问题。必要时补充 `logic --paragraph-arc`。

```bash
uv run python $SKILL_DIR/scripts/check_style_zh.py main.tex --section introduction
uv run python $SKILL_DIR/scripts/deai_check.py main.tex --section introduction
uv run python $SKILL_DIR/scripts/check_claim_forward.py main.tex --section introduction
```

3. 依下文保留清单与改动准入写出单元润色稿。当前小节包含的原有标题命令与标题文本原样保留；邻域只帮助理解，不复制到稿中。
4. 将润色稿写入临时文件，运行 `--verify --unit <id> --revised <file>`；若使用独立原文片段则改用 `--original <file>`。Error 必须修正后重新核对；逐项解释 B 档候选。核对失败或尚未运行时明确说明，不能标记已通过。
5. 按下文顺序交付润色稿、修改说明、四字段块和核对摘要。`PASS-SCRIPT` 只证明脚本覆盖的差异未阻塞，因果、范围、强度和术语语义仍须复核。

核对时可用 `--terms` 提供已有术语表。明确列出的术语片段不参与 `UP-STRENGTH` 计数，其计数变化仍报 `UP-TERM`。未配置的术语或普通用法仍可能触发强度候选；逐项读取报告上下文，区分技术名词、一般表述与真实结论词，不按计数机械加强或削弱原文。

## 必须保留

- 专有名词、理论名、变量名；不为“高级表达”更换术语。
- 数字、单位、实验参数、引文编号与图表编号。
- 因果与相关关系，以及显著、不显著、可能等结论强度，不得抬升也不得擅自削弱。
- 研究对象、时间范围、方法步骤、样本参数；不新增数据、文献、概念、机制或结论，不扩大适用范围。
- `\cite{}`、`\ref{}`、`\label{}`、数学环境和模板宏原样保留；不伪造文献或实验结果，不改变受保护术语。脚本对数学空白的规范化不构成改写数学的许可。

## 改动准入与修改偏好

只改已核实的脚本命中、口语化、语法错、句间逻辑断层和欧化长句；脚本候选须先看上下文。通顺句不动，不追求整齐句式。遇到需要新增事实才能补足的逻辑缺口，用 `【待补证】` 提示作者，不代填答案。

一段一中心、结论先行的诊断依据见 [段落弧线](paragraph-arc-zh.md)，不得为满足形式改动事实关系。优先用统计、比较、识别、检验、归纳、检测、计算等与原研究动作相符的动词。方法段按原流程拆句，保留步骤顺序与参数；冒号、分号的句间逻辑按 [中文学术风格](academic-style-zh.md#punctuation-prose) 判断，不另设句长阈值。

无信息垫话依据 [deai](../modules/deai.md) 的诊断判断。段内无信息的“综上所述”可删，章末小结或结论章首句的“综上所述”保留；“本章/本节将……”导语保留，按 [结构指南](structure-guide.md) 核对其功能。连接词由位置和证据决定，不按黑名单机械删除。

“不仅……而且……”只有两分句都有证据时保留；无依据的递进或“不是……而是……”反差改为原事实支持的陈述，不补造第二项优势。的字链和元评论尾巴由 `[LLM]` 判断，不新增脚本类别。重复免责与泛泛局限只按 [主张前置](claim-forward-zh.md) 在单元内移到对应事实附近，不删除限制、不利对比或非主线结果；不把该模块的加强候选直接套入本协议。

## 交付顺序

先给完整单元润色稿；再给“修改说明”，只含三类：删除了哪些无信息表达；调整了哪些句子逻辑或结构；哪些位置缺证据需作者补充（沿用 [去 AI 指南](../deai/guide.md) 的 `【待补证】`）。无实际改动的一类写“无”，不解释未改内容，不重复正文。

然后给 `[LLM]` 四字段块；字段与风险闭集沿用 [路由契约](../modules/routing-rules.md)：

```latex
% POLISH (source.tex:L10-L14) [Severity: Info] [Priority: P3] [LLM]: 单元润色提案
% Changed:       <实际改动，或 none>
% Protected:     <受保护内容，或 none>
% Meaning-Check: <PRESERVED | NEEDS-LLM>
% Risk-Flags:    <none | not-assessed | lexical-substitution | whitespace-normalized | overstatement | ambiguity | terminology-drift | invented-claim>
```

最后附准确核对命令、退出码、各核对码命中数、`BLOCK` 或 `PASS-SCRIPT` 及未决语义问题。`[Script]` 恒为 `Meaning-Check: NEEDS-LLM`，不输出 `Risk-Flags`；`[LLM]` 的 `PRESERVED` 是待作者核对的提案。

## 自检三问

1. 删除测试：删掉这句会损失信息、限制或证据吗？会则保留其内容。
2. 邻段对照：是否引入了相邻原文没有的整齐句式或风格？保留自然表达，不提取范例论文指纹。
3. 强度对照：按 [过度声称阶梯](over-claim-guard.md) 检查，因果、范围、术语及结论强度是否仍与原文一致？任何抬升或削弱都不能以“润色”为由接受。

## 整章与全文请求

先用 `--plan` 列清单，整章可加 `--section`。按清单顺序逐单元读取、润色、核对和交付，不生成整章替换稿。超过 1200 个可见汉字的小节按其内部自然段单元逐段处理；只读邻域始终不进入润色稿。无 depth-3 标题时只处理自然段，不用 depth-2 冒充小节。
