# 审核指南

如何使用纸质审核技巧并解释其结果。

## 快速入门

```bash
# Basic quick audit
python scripts/audit.py paper.tex --mode quick-audit

# Deep review
python scripts/audit.py paper.tex --mode deep-review

# Quality gate (pass/fail)
python scripts/audit.py paper.pdf --mode gate --pdf-mode enhanced

# Chinese thesis
python scripts/audit.py thesis.tex --lang zh --venue thesis-zh
```

## 模式选择指南

|设想|推荐模式|为什么|
|----------|-----------------|-----|
|“我的论文准备好提交了吗？”| `quick-audit` |快速准备情况分析|
|“距离提交还有三天时间”| `quick-audit` |最后一周的机械准备情况屏幕|
|“评论家会怎么说？”| `deep-review` |审阅者风格的问题包和路线图|
|“我的学生可以提交这个吗？”| `gate` |快速通过/失败检查|
|“在截止日期前快速进行健全性检查”| `gate` |最快，仅检查必需品|
|“我想要详细的反馈”| `deep-review` |最全面的输出|

## 了解报告

### 快速审核报告

快速审核报告包含：

1. **执行摘要**：总分和问题数一目了然
2. **分数表**：每个维度的分数以及问题计数（严重/主要/次要）
3. **问题列表**：所有发现均按严重程度排序
4. **预提交清单**：每个清单项目的通过/失败
5. **提交前调查结果**：最后一周对破折号进行确定性检查，
AI-tone 术语频率、抽象结果差距、LaTeX 引文/标签/方程
卫生、段落形状的弱信号和具体的标题

**如何阅读分数**：
- **5.0+**：非常好 - 仅进行了细微的改进
- **4.0-5.0**：良好 — 解决主要问题
- **3.0-4.0**：需要工作——需要进行重大修改
- **< 3.0**：主要问题——考虑重组

### 深度审查报告

深度审核工作流程现在会产生两个互补的审核者工件：
- **`review_report.md`**：证据丰富的审计包，包含结构化的主要/中等/次要调查结果、委员会产出和路线图详细信息
- **`peer_review_report.md`**：一份精美的期刊风格审稿人报告，其中包含**摘要**、**主要问题**、**次要问题**和**建议**

深度审查报告补充道：
- **总体评估**：简短的校准审稿人摘要
- **主要/中等/次要问题**：引用锚定的结构化调查结果
- **修订路线图**：优先修复列表
- **建议**：分数摘要（如果需要）
- **阶段 0 自动发现**：脚本上下文，包括`PRESUBMISSION`
发现。全面/编辑的关注可能会促使高信号机械问题进入
这`pre_submission_readiness`审查通道;方法论/理论/文献/逻辑
焦点使它们远离最终的焦点包。

同行评审报告补充道：
- **摘要**：1-2个学术评论语气的简洁段落
- **主要问题**：对章节或引用锚点的编号有效性威胁问题
- **小问题**：仍值得修改的次要问题
- **推荐**：`Accept | Minor Revision | Major Revision | Reject`

### 门报告

二元判决：
- **通过**：通过所有强制性检查，没有严重问题
- **失败**：发现阻塞问题 - 必须在提交前修复

`PRESUBMISSION`主要和次要调查结果仅供参考`gate`;他们不
除非脚本报告“严重”，否则门将失败。

## 严重性映射

|预提交来源分类|快速/门严重性|深入审查捆绑严重性|
|-------------------------------|---------------------|-----------------------------|
|批判的|严重/P0|专业+门禁者|
|主要的|专业 / P1|缓和|
|次要的|未成年人/P2|仅次要或阶段 0|

## PDF 输入注意事项

PDF 模式有其固有的局限性：

|特征|乳胶/打字机|PDF基础版|PDF 增强版|
|---------|-------------|-----------|-------------|
|断面检测|精确的|启发式|好的|
|数学验证|满的|不可用|不可用|
|格式检查|满的|跳过|跳过|
|图参考|满的|跳过|跳过|
|语法分析|满的|好的|好的|
|逻辑分析|满的|好的|好的|
|参考书目|满的|跳过|跳过|
|提交前文本检查|满的|纯文本|纯文本|
|提交前源卫生|满的|跳过|跳过|

**建议**：尽可能使用源文件 (.tex/.typ) 以获得最大
准确性。当来源不可用时，使用 PDF 模式进行快速审阅； PDF模式
将明确跳过引用关系、标签、编号方程和来源标题
检查。

## 解决问题

### 优先顺序
1. **严重 (P0)**：必须修复 - 这些可能会导致拒绝
2. **专业（P1）**：应该修复——这些会显着削弱论文的强度
3. **次要 (P2)**：很好修复 - 这些改进了抛光

### 常见的关键问题
- 缺少图/表参考
- 编译错误
- 占位符文本（TODO/FIXME）
- 盲投作者姓名

### 常见的主要问题
- 长而复杂的句子
- 方法论中的逻辑差距
- 基线缺失或消融
- 人工智能追踪写作模式

### 常见的小问题
- 小语法问题
- 符号不一致
- 违反风格指南

## 修复后重新审核

解决问题后，重新运行审核以验证改进：

```bash
# Before fixes
python scripts/audit.py paper.tex -o report_before.md

# After fixes
python scripts/audit.py paper.tex -o report_after.md
```

比较分数以跟踪改进情况。
