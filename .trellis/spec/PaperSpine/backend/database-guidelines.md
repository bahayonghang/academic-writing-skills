# Configuration And State

There is no database layer. Persistent state is JSON or generated Markdown, and
the code must preserve user-owned config when updating installs.

State files and manifests:

- `dist/paperspine_version.json` is the canonical version manifest.
- `.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json` are updated
  from the canonical version.
- `~/.paperspine/install_state.json` records the installed version, source, and
  targets.
- `~/.paperspine/config.json` is preserved across updates.
- `paper_rewriting_output/paper_spine_config.json` and companion Markdown files
  are generated by `intake_wizard.py`.

Local pattern:

- Read and write JSON with explicit UTF-8 and a trailing newline.
- Keep version/state logic in the scripts, not in the README.
- Treat `paper_rewriting_output/` as generated workspace state, not checked-in
  source.
- Preserve config fields that belong to the user when syncing or updating.

Reference files:

- `ref/PaperSpine/src/scripts/paperspine_update.py`
- `ref/PaperSpine/src/scripts/intake_wizard.py`
- `ref/PaperSpine/src/scripts/sync_local_installs.py`
- `ref/PaperSpine/tests/test_update_script.py`

Avoid:

- Writing a new persistence format when JSON state is already established.
- Overwriting user config just because a new dist version shipped.
- Treating dist manifests as mutable source during local editing.
