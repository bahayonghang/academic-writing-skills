# 波兰语指南

## 风格目标

### 风格 A：简单、精确
- 喜欢主动语态，句子平均少于 25 个单词
- 消除模糊词：“有点”、“相当”、“相当”
- 强动词：“演示”>“展示”、“使用”>“使用”、“实现”>“获得”
- 切勿以“在本文中，我们......”作为引言开头
- 转换：“为了”→“为了”，“可以看出”→（删除）

### 风格 B：叙事流畅
- 主题句必须预览段落
- 在各部分之间添加 1-2 个句子桥梁
- 用明确的名词替换悬空的“this”
- 路标过渡：“在此基础上构建”、“至关重要”
- 摘要结构：问题→为什么困难→我们的方法→关键结果

### 风格 C：正式学术
- 方法/结果中可接受的被动语态
- 对冲实证主张：“建议”、“表明”、“似乎”
- 正式词汇：“调查”>“看”、“实质性”>“大”
- 所有标题中的完整句子（不是片段）

## 评论家协议

### block_mentor = true 标准
仅在以下情况下设置：
1. logic_score <= 2（争论如此破碎抛光还为时过早），或者
2. 部分在结构上不存在（未检测到），或者
3. 严重级别的阻止程序适用于本节

### 逻辑评分标准 (1-5)
- 5：完美流程，每项主张都有理有据
- 4：微小的差距，一个不合理的假设
- 3：明显的差距，会让细心的审稿人感到困惑
- 2：重大错误、不受支持的主张、缺少基线→blocks_mentor
- 1：根本不连贯→blocks_mentor

### 表达评分标准 (1-5)
- 5：可发表，无需改进
- 4：每节1-3个弱句
- 3：几个尴尬的结构
- 2：需要重度抛光
- 1：基本不清楚

## 导师协议

### 优先顺序
1. 清晰度障碍（无法解析的句子）
2. 特定于风格的转换（上面的 A/B/C 规则）
3. 按顺序批评 top_issues
4. 预先检查本节的 expression_issues
5. 字级改进

### 禁止的导师行为
- 重写整个段落而不显示原文
- 更改引用的声明或添加/删除引用
- 添加新的技术内容
- 消除限制或负面结果

### 上下文窗口管理
- Mentor 通过 Read(offset=start-1, limit=end-start+1) 仅接收目标部分
- 对于> 1200字的部分：编排器在小节边界处分割，
产生两次导师电话
