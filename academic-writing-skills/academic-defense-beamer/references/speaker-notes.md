# 讲稿格式

本文件规定答辩讲稿的五栏格式与 `notes.md` 的输出格式。每页的秒数取自规划文件，计算方法见 [时长预算](time-budget.md)。可能提问的类别见 [答辩提问准备](qa-prep.md)。

## 五栏

| 栏目     | 内容                                                     | 长度              |
| -------- | -------------------------------------------------------- | ----------------- |
| 说什么   | 本页的口语讲稿：先说结论，再说依据；引用图号、表号、式号 | 内容页 150–250 字 |
| 要点     | 本页最重要的一句话，与结论句一致或更短                   | 一句              |
| 时长     | 本页的秒数，取规划文件中的 `notes.seconds`               | 整数秒            |
| 过渡     | 引出下一页的一句话                                       | 一句              |
| 可能提问 | 评委可能就本页提出的问题                                 | 1–2 条            |

150–250 字为初始区间，未经标定。封面、目录页与致谢页的「说什么」不受该区间限制。

## 写法

- 用第一人称口语，例如「本文」「我们」。不逐字朗读页面文字。
- 讲图时先说图号，再说看图的顺序，例如「如图3-2所示，左侧为……右侧为……」。
- 只讲论文中已有的数字，数字带单位与对照基准。
- 章末页的过渡引出下一章，例如「为解决问题二，下面汇报第 4 章」。
- 总目录页的讲稿说明汇报结构，例如「我将按照论文的 7 章内容进行汇报」。
- 致谢页的讲稿为「汇报完毕，请各位老师批评指正」。

## notes.md 格式

构建脚本按帧序为每帧写一节。节标题为「## <序号> <帧标题>（<帧 id>，<页角色>，<秒数> 秒）」，其下五行依次为五栏。文末写全部页的秒数合计与目标秒数（60 × 分钟数）。

```markdown
## 8 3.1 引言（c3-intro，intro，51 秒）

- 说什么：本章针对问题一展开研究。如图3-1所示，技术路线分为三步……
- 要点：本章针对问题一提出示例方法一。
- 时长：51 秒
- 过渡：下面先说明本章研究的问题。
- 可能提问：为什么选择该技术路线？；与第 2 章的框架是什么关系？
```

- 「可能提问」有两条时用「；」分隔。
- 规划文件中尚未填写的栏目保留占位符「〔待填写〕」。质量门会报告剩余的占位符。
