# 工作流程和最佳实践

如果用户请求完整审核，则按顺序执行：

1. 格式检查 → 修复关键问题
2. 语法分析→修正错误
3. 去AI编辑→减少AI书写痕迹
4. 长句分析→简化复杂句子
5. 表达重组→提高学术语气

## 最佳实践

1. **从编译开始**：在其他检查之前验证文档是否已编译
2. **迭代细化**：一次应用一个模块以实现更好的控制
3. **保留受保护的元素**：切勿修改`@cite`, `@ref`, `@label`, 数学环境
4. **提交前验证**：在接受更改之前查看所有建议
5. 与版本控制 (git) 一起使用来跟踪更改

## 修改顺序（逻辑→句子→词汇，不要颠倒）

当请求需要多个抛光通道时，请按此顺序应用更改并执行
不反转它：

1. **论证/逻辑** — 段落顺序、缺失或重复的主要信息、章节转换。
2. **句子结构**——分割过长的句子，被动→主动，前置高信息内容。
3. **词汇/格式** — AI 语气单词、数字/单位格式、短划线用法、首字母缩略词一致性。

为什么顺序被固定：在固定之前润色句子的措辞（步骤 3）
当步骤 1 稍后删除或合并该结构（步骤 1）时，就会浪费精力
段落。由粗到细效率提高数倍。
