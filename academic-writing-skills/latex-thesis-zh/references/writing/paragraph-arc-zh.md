# 中文学位论文段落弧线

本指南把“段落是否有起、有落、有接口”拆成可复核的形态观察。脚本只定位首句、末句、
相邻段接口和段内展开，不判断论点真伪，也不自动改写正文。

## 使用入口

```bash
uv run python scripts/analyze_logic.py main.tex --paragraph-arc
uv run python scripts/analyze_logic.py main.tex --paragraph-arc --section introduction
```

`--paragraph-arc` 是附加开关；不传时默认 `logic` 输出不变。`--section` 只缩小到已有章节
作用域，`--first-chapter` 仍只服务章号语义，不参与段落弧线定位。

所有 finding 均为 `[Script]` 观察、默认 Info/P3，并含 `Meaning-Check: NEEDS-LLM`。
只有绪论或相关工作中连续 3 个合格段同时缺少首句总领与末句收束时，额外生成一条
Minor/P2 汇总观察；单项 finding 不升级。

## 检查边界

- 段落至少含 40 个汉字；标题后的首个导语段、列表项、以受保护环境收尾的段落不检查。
- 公式、图、表、算法、代码和列表构成硬边界；`P-ARC-LINK` 不跨标题或这些环境连接段落。
- `abstract`、`conclusion`、`acknowledgment`、`appendix`、`organization`、`summary`
  不进入段落弧线检查。
- 脚本不复制完整原句到报告，不改 `\cite{}`、`\ref{}`、`\label{}` 或数学环境。
- 术语真相源为 [`paragraph-arc-terms.yaml`](paragraph-arc-terms.yaml)；YAML 缺失或字段无效时，
  脚本按字段回退同值内置表。

## 四项形态观察

| 代码 | 可复算信号 | 人工复核问题 |
| --- | --- | --- |
| `P-ARC-LEAD` | 首句较短且无判断谓词、空过渡、近乎纯引用，或只有数值/单位 | 首句是否明确本段对象、问题或判断？ |
| `P-ARC-CLOSE` | 末句未命中回指式或前瞻式标记 | 末句是否完成回扣，或为下一段建立接口？ |
| `P-ARC-LINK` | 后段无显式承接，且端点 token Jaccard 四舍五入到 4 位后 `< 0.0200` | 两段之间是递进、转折、因果还是并列？ |
| `P-ARC-FLAT` | 单句成段，或段内各句均为作者/年份罗列 | 是否需要增加比较、解释或分解层？ |

`P-ARC-LINK` 的阈值比较是严格小于：`score == 0.0200` 通过，`score < 0.0200` 才报告。
任一 token 集为空时 Jaccard 为 `0.0`；端点少于 15 个汉字时只检查显式承接标记。
相关工作中的作者罗列继续由 A1 负责，`P-ARC-FLAT` 不重复报告这一形态。

## 三类段落范式

段落不是固定句数模板。下面的“总领—展开—收束”只描述论证角色，作者可按证据量调整句数。

| 段落角色 | 首句任务 | 展开任务 | 末句任务 |
| --- | --- | --- | --- |
| 背景段 | 界定研究对象与运行语境 | 给出事实、约束或已有认识 | 收束到与本研究相关的条件 |
| 问题段 | 明确现象、瓶颈或待解关系 | 解释影响范围与现有方案边界 | 推出需要回答的问题 |
| 方案段 | 声明本段采用的机制或分析对象 | 交代输入、处理与输出关系 | 回扣设计依据或连接下一模块 |

避免把范式写成“首先—其次—最后”的排版清单。首句应承载判断，展开句应提供证据或解释，
末句应完成本段在全文论证中的角色。

## 回指与前瞻收束

回指式收束回答“本段证明或说明了什么”，常见形态包括“因此”“由此”“综上”“表明”；
前瞻式收束回答“这一结果为后续什么工作提供条件”，例如“为后续参数辨识提供输入”。
二者都不是必填词表：脚本未命中只意味着需要人工复核，不能据此断定段落不完整。

段间接口优先用语义关系而非机械连接词：

- 回指：`上述`、`该`、`这一`、`前述`；
- 递进或并列路线：`在此基础上`、`另一条路线`、`另一组`、`另一方面`；
- 问题到方案：`针对上述`、`基于此`；
- 多链归纳：`综合`。

## 与 AXES 的关系

AXES 描述单段内部的 Assertion、eXample、Explanation、Significance 四类角色；P-ARC 描述这些
角色在可见文本中的入口、出口和相邻段接口。二者不是一一映射：

跨标题的小节承接、交棒与父节角色由 `S-CTX-*` 负责；其合格段有意保留标题后的首段。

| AXES 角色 | P-ARC 观察面 | 边界 |
| --- | --- | --- |
| Assertion | `P-ARC-LEAD` 提供首句复核入口 | 脚本不判断断言是否正确 |
| eXample / Explanation | `P-ARC-FLAT` 提醒展开层可能不足 | 单句也可能合法，须结合段落目的 |
| Significance | `P-ARC-CLOSE` 观察回扣或前瞻形态 | 无固定标记不等于无意义 |
| 段间关系 | `P-ARC-LINK` 观察显式承接或词面重叠 | 低重叠不能证明语义断裂 |

## 原创抽象示例

**背景段**：在线质量变量存在观测延迟，这是连续运行判断必须面对的基础约束。多源传感器
虽然提供了高频过程记录，但其采样节拍与标签反馈并不同步。由此，状态表示需要同时保留动态
信息与时间对应关系。

**问题段**：现有离线估计依赖固定采样窗口，难以覆盖工况切换后的分布变化。窗口内统计量
可以描述局部波动，却不能说明稀疏标签如何约束连续状态。该差距引出了异步条件下的表示学习问题。

**方案段**：针对上述约束，本节构建条件状态编码机制。该机制以多源记录为输入，在统一时间
索引下形成连续表示，并把标签条件传递给估计器。所得表示为后续质量预测与误差分析提供输入。

这些示例只展示角色和接口，不承载具体论文的事实、数据、方法贡献或引用。
