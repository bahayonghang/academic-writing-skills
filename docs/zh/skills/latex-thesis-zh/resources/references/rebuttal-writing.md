# 回复写法

本文件规定「博士生修改说明」中意见、回复与修改位置的写法，粘贴用的纯文本等价 Markdown 规则，不采纳与后续工作的写法，语气与页码口径，并给出三则合成示例。流程与台账字段见 [回复流程](rebuttal-workflow.md)，检查码见 [回复质量门](rebuttal-gate.md)。

规则来源：国内高校学位论文评阅意见修改说明的填写要求（修改情况写具体内容，不能只写「已修改」；每位专家的意见单独回复）与国外学位论文修改表的写法（写明修改位置与页码，页码指修改稿）。

## 全文结构

`rebuttal_build.py` 按台账生成 `responses/response-all.md`：

```text
博士生修改说明

总体说明：感谢各位评阅专家对本论文的审阅与指导。2位评阅专家共提出5条意见，拆分为8项逐项处理，其中修改已有内容3项、补充新内容2项、在回复中说明1项、列为后续工作1项、未采纳1项。下文页码均指修改后论文。

一、评阅人1意见的修改说明

意见1：<评阅原文>

回复：<回复正文>

修改位置：<位置>

意见3：<评阅原文>

（1）回复：<子项 a 的回复>

（1）修改位置：<子项 a 的位置>

（2）回复：<子项 b 的回复>

（2）修改位置：<子项 b 的位置>

二、评阅人2意见的修改说明

…
```

- 总体说明由脚本生成：感谢一次，写意见总条数、拆分后项数与各处理方式计数。逐条回复中不再写感谢。
- 每位评阅人一节，节内自足。`response-R<n>.md` 只含该评阅人的一节，标题行为「评阅人N意见的修改说明」，不含总体说明。
- 一条意见一条回复。不同评阅人的同一问题各写全文，脚本在回复末尾加「（与评阅人1意见3（1）一并修改）」。
- `status` 不是 `done` 的条目，回复与修改位置渲染为「〔待填写〕」。论文未修改时修改位置渲染为「无（论文未修改）」。
- `review-result.md` 只有一行：`总体评价 1（A）；总体评价 2（B）`，用于填写表格中的预评审结果栏。

## 意见

- 「意见N：」后为评阅原文，脚本从 `workspace/reviews/R<n>.md` 取整条原文，不改写。
- 原文超过 160 字时，在台账 `quote_short` 中写首尾摘录，以「……」相连，每段都必须是原文的逐字子串。

## 回复

1. 首句写处理动作与具体内容：改了什么、补了什么、为什么不改。不只写「已修改」「已按意见修改」。
2. 写到读者不翻论文也能判断是否回应了意见的程度：符号补了哪些，图改了哪几处，节里补了哪项分析。不把整段新增正文贴进回复。
3. 数字只取自修改后论文或评阅原文。回复中带小数或百分号的数字须能在论文可见文本中找到，否则 check 报 R-NUM-SRC。
4. 完成用语（已修改、已补充、已增加、已删除、已调整、已完善、已重绘、已修正、已更正、已统一）只用于论文确实改过的条目。`clarify` 与 `decline` 不用完成用语。
5. 论文中已有相应内容（`clarify`）：写出原文位置与内容要点，例如「第3.2节第2段给出了该假设的适用条件」。
6. 一条回复一般 1–3 句。子项多时拆子项，不写长段。

### 不采纳与后续工作

- `decline`：给学术理由，例如问题范围、研究假设、已有文献的通行做法、指标的适用条件。不以时间、经费或工作量为理由（check 报 R-TONE）。
- `partial`：先写已改部分，再写未采纳部分及理由。
- `future_work`：写出答辩前无法完成的原因（数据条件、平台条件、需要的新实验），写明列为后续工作。可在论文「局限与展望」中补充讨论，并把该节写入修改位置。不把计划中的实验写成已完成，不预测实验结果。
- 同一问题被多位评阅人提出时，各条的处理方式应一致；一处修改、一处不修改时 check 报 R-SHARED。

### 语气

- 陈述事实与处理内容。不贬抑评阅人（不写「专家误解了」「显然」「众所周知」）。
- 不在每条回复开头重复同一句（例如每条都以「感谢专家的宝贵意见」开头）。同一开头出现 3 次以上时 check 报 R-TONE。
- 中文去 AI 腔：不写「值得注意的是」「需要指出的是」等提示语；不用「首先……其次……最后……」排比；不写升华句；不用「不是 A，而是 B」句式先立后破；不用「从而」「进而」做段落过渡。

## 修改位置

- 优先在台账 `locations` 中写 LaTeX 标签或 bib 键。脚本用修改后论文的 aux 渲染当前编号与页码。

| 位置                  | 渲染                                   |
| --------------------- | -------------------------------------- |
| 图、表、式、算法标签  | `图2-8（第28页）`、`式(2-1)（第14页）` |
| 编号与送审版本不同    | `原图2-1，现图2-2（第13页）`           |
| 章标签                | `第6章`                                |
| 节标签                | `第2.4节（第25页）`                    |
| bib 键                | `参考文献[24]`                         |
| 文件 + 节号（无标签） | `第6.1节`                              |

- 多个位置以「；」分隔。
- 页码口径：页码指修改后论文。论文最后一次编译之后再运行 build，使页码与提交给学校的版本一致。tex 晚于 aux 时 check 报 R-PAGE-STALE。
- 回复正文中提到图表编号时，写修改后的编号；只写原编号时 check 报 R-RENUM。

## 纯文本等价 Markdown

responses 中的文件直接复制原文与从 Markdown 渲染视图复制，得到相同文字。规则：

- 只用普通段落，段与段之间空一行。
- 行首不用 `#`、`>`、`-`、`*`、`+`、`1.`、`1)`。编号写成「意见1：」「（1）回复：」「一、评阅人1意见的修改说明」。
- 行内不用 `**`、`__`、反引号、`[文字](链接)`、HTML 标签、`|`、`$`、`\`、`[^`。
- 行尾不留两个以上空格。

台账 `response` 中的文字原样进入 responses，所以 `response` 也遵守以上规则。公式写成文字或论文中的编号（「式(2-1)」），不写 LaTeX 源码。

## 合成示例

以下示例的题目、编号、页码与内容均为虚构。

### 示例一：修改已有内容（revise）

台账条目：

```yaml
- id: R1-2
  reviewer: R1
  item: 2
  quote: 图3-4的坐标轴缺少单位，图例颜色与曲线不对应。
  category: figure
  severity: Minor
  priority: P2
  anchors:
    - text: 图3-4
      kind: figure
      label: fig:c3-error
      base_number: 3-4
      base_page: 46
  action: revise
  status: done
  owner: drawio
  plan: 重绘该图，补坐标轴单位，统一图例颜色。
  response: 已重绘该图，横轴标注时间单位分钟，纵轴标注流量单位辆每小时，图例颜色与对应曲线一致。
  locations:
    - label: fig:c3-error
  evidence:
    kind: git_diff
    files: [figures/chapter3/error.png]
    note: ""
```

渲染结果（修改后论文在该图之前新增一幅图，编号变为3-5）：

```text
意见2：图3-4的坐标轴缺少单位，图例颜色与曲线不对应。

回复：已重绘该图，横轴标注时间单位分钟，纵轴标注流量单位辆每小时，图例颜色与对应曲线一致。

修改位置：原图3-4，现图3-5（第47页）
```

### 示例二：补充新内容（add）

台账条目：

```yaml
- id: R2-1
  reviewer: R2
  item: 1
  quote: 第4章实验部分缺少与基线方法的显著性检验。
  category: experiment
  severity: Major
  priority: P1
  action: add
  status: done
  owner: latex-thesis-zh
  plan: 在第4.4节补充重复实验的配对检验，结果列表。
  response: 已在第4.4节补充5次重复实验的配对t检验，检验对象为本文方法与三种基线方法的误差，结果列于表4-6。
  locations:
    - label: sec:c4-4
    - label: tab:c4-ttest
  evidence:
    kind: git_diff
    files: [chapters/chapter4.tex]
    note: ""
```

渲染结果：

```text
意见1：第4章实验部分缺少与基线方法的显著性检验。

回复：已在第4.4节补充5次重复实验的配对t检验，检验对象为本文方法与三种基线方法的误差，结果列于表4-6。

修改位置：第4.4节（第68页）；表4-6（第69页）
```

### 示例三：列为后续工作（future_work）

台账条目：

```yaml
- id: R2-3
  reviewer: R2
  item: 3
  quote: 建议在其他城市的数据集上验证方法的泛化能力。
  category: generalization
  severity: Major
  priority: P1
  action: future_work
  status: done
  owner: latex-thesis-zh
  plan: 在展望中补充跨城市验证的数据条件与实验设计，列为后续工作。
  response: 跨城市验证需要与本文数据相同采样间隔和检测器布设的数据，目前尚无满足该条件的公开数据集。本文在第6.2节展望中写出了跨城市验证所需的数据条件与实验设计，将其列为后续工作。
  locations:
    - label: sec:c6-2
  evidence:
    kind: git_diff
    files: [chapters/chapter6.tex]
    note: ""
```

渲染结果：

```text
意见3：建议在其他城市的数据集上验证方法的泛化能力。

回复：跨城市验证需要与本文数据相同采样间隔和检测器布设的数据，目前尚无满足该条件的公开数据集。本文在第6.2节展望中写出了跨城市验证所需的数据条件与实验设计，将其列为后续工作。

修改位置：第6.2节（第121页）
```

如果论文未补充展望文字，`locations` 为空，`evidence.kind` 为 `none`，修改位置渲染为「无（论文未修改）」。
