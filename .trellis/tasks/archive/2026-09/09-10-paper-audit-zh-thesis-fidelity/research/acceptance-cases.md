# 审查验收场景与证据等级

这是未来实施验收合同，不是已运行的模型评测。复用旧 C1 八场景的事实与反例，新增 audit 消费链输入；执行前从旧归档研究材料提取纯输入，不把旧答案或本表预期交给被测 reviewer。

旧 C1 输入与原始规则位于 `.trellis/tasks/archive/2026-09/09-10-thesis-zh-guidance-fidelity/research/sampling-before.md` / `sampling-after.md`；这些混合了规则和用户输入，不能整份作为新 reviewer 论文输入。公开最小材料为 `academic-writing-skills/latex-thesis-zh/evals/fixtures/guidance_fidelity.tex`。

## 执行和判分方法

1. 冻结修改前实际 reviewer 输入包、技能规则散列、24 条历史 eval / 20 条 trigger 的对象快照。保留全部旧对象顺序，只在尾部新增用例，不复用历史 ID 空洞。
2. E09—E14 的可确定部分用真实 checker、workspace、consolidation、quote verification API/CLI 跑正反例。断言内容、来源与严重度；完整合成稿的其他既有缺项单列，不把整条命令非零当成本目标失败。
3. E01—E08、E12 的语义与 E15 使用相同输入分别获得旧/新 `zh_thesis_review` 和 `claims_vs_evidence` reviewer 原始响应；按原 lane max 8 分批，避免预算将目标样例挤掉。最终将至少一例真实 reviewer JSON 放进 `artifacts/comments` 后合并和引用核验。
4. 独立 reviewer 只负责判分，不重写被测响应。每例逐项核对事实保真、证据强度、学校/体裁适配、语义边界、定位和只审不改。任一禁止结果出现即 FAIL；无问题的合法反例允许返回空 issue 数组，覆盖说明放在现有 review summary/notes，不能为凑条数造问题。
5. 记录实际运行方式、次数、输入/规则散列与原始输出；同 agent 批次不能冒充独立实验，未知模型/用量遥测留空。静态 tests 证明可加载和结构契约，不能替代实际响应核读；缺少运行能力时相关 AC 未完成，其他工作仍可继续。
6. 只有语义场景全部满足预期、真实消费链通过、完整 CI/资源/docs 通过才标记实施完成。真实论文、学校模板视觉、五宿主/provider benchmark 仍单列 UNVERIFIED，不要求这些外部项目作为本增量任务的完成门槛。
