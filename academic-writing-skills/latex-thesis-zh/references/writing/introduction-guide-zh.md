# 绪论（第 1 章）写作专章指南

面向中文博士/硕士学位论文的绪论写作与诊断。诊断入口：

```bash
uv run python $SKILL_DIR/scripts/analyze_literature.py main.tex --intro-citations --bib refs.bib
uv run python $SKILL_DIR/scripts/analyze_logic.py main.tex --intro-mainline
```

> 本文所有阈值为多校规范与写作实践的常见口径（出处见各节），**最终以本校研究生院最新
> 撰写规范为准**；命令行均可覆盖默认值。

## 六节漏斗骨架与篇幅配比

绪论总量约 1 万字、不超过 20 页（专家共识："写到点子上，20 页足矣"）。

| 节 | 职能 | 占比参考 |
| --- | --- | --- |
| 研究背景与意义 | 领域语境 -> 工程/理论价值，落到"为什么值得做" | ~15% |
| 国内外研究现状 | 分主题综述 + 演进脉络 + 图表化归纳 | ~45% |
| 现存问题/关键挑战 | 从综述边界推出待解问题 | ~10% |
| 研究内容与创新点 | 科学问题 -> 研究内容 -> 创新点四方闭合 | ~20% |
| 研究方法/技术路线（可选，依学校） | 总体方案与技术路线图 | ~5% |
| 论文组织结构 | 各章递进关系（勿机械罗列标题） | ~5% |

首段必须完成三层漏斗：**领域背景 -> 技术瓶颈 -> 本文围绕什么展开**，不可从术语或
系统细节直接切入（脚本检查 L-FUN）。

## 引用配额（B1/B4 默认阈值及出处）

| 指标 | 默认值 | 出处 |
| --- | --- | --- |
| 绪论唯一引用数 | 120~160 篇或更多（博士档） | 全文 >=100 篇为北工大/哈工大等校规范，绪论承担大部分引用 |
| 近三年文献占比 | >=30% | 常见严口径（宽口径为近五年 >=1/3，且须含近两年文献） |
| 近五年文献占比 | >=50% | 同上 |
| 外文文献占比 | >=1/2（全文口径） | 北工大等校规范；脚本暂不检查，人工核对 |

选文配比策略（与 `bib-search-citation` 协作检索时执行）：

- 每个主题簇 = **奠基文献 1~2 篇 + 近三年文献 2~3 篇**，中外来源均衡；
- 同一作者/团队多篇**拆开分述**，比较其方法演进与局限，不整簇塞进一个 `\cite`
  （脚本检查 B2/B3）；
- 一手文献优先：引谁的工作就引谁的原文，不引二手转述；
- 教材、报纸、未公开报告原则上不作为论证依据；
- **引用不足时只能从用户 .bib 或真实文献库补检，绝不允许编造条目。**

## 国内外研究现状的组织与可视化（B5）

组织方式任选其一并显式声明：

1. **国内外分述**：先国外后国内（或相反），末尾对比差异与联系（"总-分-总"）；
2. **按主题混排**：小节开头声明"本节按主题组织，国内外工作在各主题内对比"
   （脚本检查 L-DOM：标题写了"国内外"就必须兑现其一）。

每个主题簇内部遵循：`共识 -> 分歧 -> 局限 -> 空白`，簇末必须有比较/让步/局限句
（literature 模块 A2）。排列从远到近：先弱相关，后密切相关。

**可视化归纳（至少一件，脚本检查 B5）**：

- **研究演进时间线图**：横轴为年代，按"萌芽期/发展期/深化期"等阶段分期，每阶段
  锚定 2~3 篇代表文献与标志性转折；
- **文献对比矩阵表**：行 = 代表工作，列 = 方法路线 / 关键假设 / 适用范围 / 局限，
  表后用一段"总-分-总"收束；
- 注意：**甘特图属于开题报告的进度安排，不放入绪论**；需要表达路线时用研究演进图
  或技术路线图。

三忌（综述常见反模式）：讲义式罗列理论流派；主观设靶贬低前人；引用来源含糊、把
前人工作与自己的工作混写。

## 科学问题凝练（L-SCI）

科学问题必须同时含**对象、问题、方法**三要素，句式模板：

```text
针对〈对象〉的〈现象/瓶颈〉，研究〈科学问题〉，拟采用〈方法路径〉。
```

判别表：

| 形态 | 示例 | 判定 |
| --- | --- | --- |
| 短名词短语 | "多速率状态重叠" | 不合格：只是主题词，无对象无方法（脚本命中） |
| 技术任务 | "开发一套软测量系统" | 不合格：工程任务，不是科学问题 |
| 合格问题句 | "针对多速率异步采样的烧成过程，研究低频质量条件如何调制高频动态特征，拟采用条件特征调制机制" | 合格：对象+问题+方法齐备、可检验 |

要求：一句话旗帜鲜明、可检验（能据以收集数据验证）；主题唯一，用假设树自顶向下
分解，不贪大求全。

## 四方闭合（L-MAP）

**科学问题 <-> 研究内容 <-> 创新点 <-> 章节安排**应一一对应。推荐做法：

- 绪论内放一张"科学问题-研究内容-创新点-对应章节"映射表；
- 条数不等时必须在正文声明原因（如"系统实现作为工程验证贡献，不与方法创新等量
  表述"）——声明后脚本降级为 Info；
- 每条创新点在结论章都有回应（logic 模块 C3）。

## 整体性写作次序

1. **主题先行**：先定全文唯一主线句，再筛选素材；与研究问题无关的内容删除；
2. **先写正文、后写绪论**：对研究有整体把握后回头提炼背景、现状与意义；
3. 综述围绕本文创新点展开——把"前人肩膀"交代清楚，衬托本文贡献；
4. 章节安排写"递进关系"（第 N 章的输出如何成为第 N+1 章的输入），不逐章复述标题。

## 输出建议格式

```latex
% 绪论引用（chapters/chapter1.tex:55）[Severity: Minor] [Priority: P2]: [Script] B3 前缀“zhao”文献 5 篇，且在第55行整簇共引
% 建议：拆开分述并比较该团队方法的演进与局限；若为不同作者请人工复核后忽略。
```
