# 工程实现与平台应用章写作适配

## Goal

让已有中文 LaTeX 论文的工程实现/平台应用章获得按章型选择的学术写作指引。父需求归属见父 PRD Task Map。

## Background

当前方法章指南只说明工程验证可放在哪里，没有独立工程章论证指南；`academic-writing-skills/latex-thesis-zh/references/modules/routing-rules.md:60` 的方法章条目含第三至第六章表述，存在按章号误套的风险。此处是文档路由风险，不声称已观测到模型误路由。见父任务 research/engineering-evidence.md。

## Requirements

- R1：在现有 logic 模块下按章内容识别工程应用章，说明与方法实验章、过程章、结论章的区别。
- R2：将运行约束、设计目标/系统属性、可证实机制和验证证据连成论证；界面按操作者任务说明。
- R3：区分离线回放、影子观察、试点和实际生产/闭环；可靠性、业务收益、跟踪效果与人工可用性分别取证。
- R4：保持方法章及相邻模块原路由；增加正反例、双语资源与能力入口，维持现有 CLI 和权限范围。

## Acceptance Criteria

- [x] AC1（R1、R4）：同为第六章的工程例与方法例按内容分流；仅有章号信息时先查正文，不凭编号运行逐方法章 E-*。
- [x] AC2（R2、R3）：技术栈/UI清单案例能产出至少一条有来源的约束—目标—机制—证据链，缺少机制事实时标缺证据，不补 API/公式/指标。
- [x] AC3（R3）：只有回放和截图时不称现场闭环、业务收益或可用性已验证；回退边界不被改成绝对安全。
- [x] AC4（R1、R4）：真正一章一方法仍走方法/逐章实验；纯软件部署 README、Typst、英文论文和审稿评分为近邻负例。
- [x] AC5（R4）：新指南可由既有 logic 入口按需到达，结果小节按需复用 RA；新 flag/module/checker 数为零，双语/manifest/契约检查通过。
- [x] AC6（R1、R2、R3、R4）：合成正反例的实际响应与逐项裁决记录完整；未运行的模型、现场、人工和视觉证据明确标注。

## Out of Scope

用户已于 2026-09-05 明确批准本任务树实施。除设计列明的目标外不清理、不增依赖、不改其他技能/论文，不提交、归档或发布。
