# 一致性模块参考

目的：复核各论文章节中的术语、缩略语和符号一致性。脚本观察只提供待复核候选，不证明语义等价。

## 术语一致性规则

1. **介绍陌生术语**：读者需要解释时再展开技术术语；按学科或模板要求给出英文对应词。
2. **保留概念区别**：深度学习与深度神经网络、机器学习与机器智能、循环神经网络与递归神经网络是不同概念，共现不构成合并名称的理由。
3. **结合语境核对命名**：内置分组提示可能的表面形式变化。既有 `--custom-terms` JSON 分组表示作者显式分组，但分组顺序和词频都不决定规范名。修改前先确认等价关系和修改理由。

## 缩略语规则

1. **首次使用时展开**：单独使用前先引入缩略语：“长短期记忆网络（LSTM）”。首次使用按装配全文的首次有效出现判断，也包括定义所在行中更早的使用。
2. **后续使用**：全称和缩略语可以因可读性需要交替使用。定义后频繁使用全称只产生可选风格候选，不要求把全部全称替换掉。
3. **每章重新引入**：重新引入有助于从后章开始阅读的读者。同章或跨章重复相同释义均合法；后章也可直接复用此前定义。检查器不要求每章重新定义。
4. **定义候选**：脚本在同一物理行的括号附近提取有界的可见全称片段，不跨句末或结构命令猜测完整名称。缺少可靠边界或可见释义不同时标注 `NEEDS-LLM`；中英文释义可能等价。
5. **标题**：按学科和模板判断缩略语是否足够熟悉、适合用于标题；脚本不判断读者熟悉程度。

## 符号统一

- **变量**：按学科和模板复核符号含义与字体。
- **上下标**：检查跨公式的惯例与指代是否清楚。
- **单位**：先核对量纲和已说明的换算，再判断同一物理量使用不同单位是否不一致。

这些属于 `[LLM]` 或作者复核。该一致性脚本不判定数学或单位等价，不修改公式、引用键、标签或源文。

## 常见问题

| 问题 | 示例 | 修复方式 |
|-------|---------|-----|
| 表面形式候选 | 作者分组的“自编码器”/“自动编码器” | 确认指代相同后再选择形式 |
| 未定义缩略语 | 未事先定义就写“使用 GAN 生成” | 添加首次使用时的全称 |
| 可见释义不同 | 一个缩略语的中英文全称 | 以 `NEEDS-LLM` 核对等价关系，不先认定冲突 |
| 可能的符号冲突 | 不同小节分别用 $x$ 表示输入和输出 | 核对作用域和含义，不自动修改数学内容 |

## 检测方式

```bash
uv run python scripts/check_consistency.py main.tex --terms
uv run python scripts/check_consistency.py main.tex --abbreviations
uv run python scripts/check_consistency.py main.tex
```

- `--terms`：统计配置的表面形式，报告命名或全称使用的可选风格候选。不证明同义关系，也不检测全部大小写不一致。
- `--abbreviations`：检查可识别的大写缩略语、首次使用顺序及可见定义候选。定义括号中的缩略语不计入单独使用次数。无定义的缩略语沿用出现两次的既有阈值并排除常用停用词；晚于首次使用的定义即使此前只用一次也会报告。
- 完整模式运行两项检查。结果是 `[Script]` 观察；语义判断在复核前仍为 `NEEDS-LLM`。

有主文件入口时，检查器消费现有 loader 的 include 展开与源位置映射，保留 include 前后的正文顺序，排除无关草稿，并报告源路径和行号。无入口时（目录、`--all-files` 或文件列表 API），分别检查文件内顺序，明确说明跨文件顺序未验证，不按文件名推断阅读顺序。缺失 include 或解码的 loader 警告保持可见；无问题结果只覆盖该范围内可读取、可识别的内容。

默认行为变化用于修正误报与假绿：不再合并不同概念，检出先用后定义，保留合法重复释义，把不确定含义交给人工复核。这些检查不证明真实论文的语义一致性。

> 逻辑与连贯性检查（非术语问题）参见 [`logic.md`](logic.md)。完整参考见 [`../writing/logic-coherence.md`](../writing/logic-coherence.md)
