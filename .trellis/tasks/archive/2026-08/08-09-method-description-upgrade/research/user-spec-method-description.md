# 方法描述规范

> 适用于中文工科学位论文中的方法章，尤其是包含多个串行、并行或监督关联模块的方法链。

## 1. 目标与规则等级

方法描述应使读者在不反推作者意图的情况下回答五个问题：

1. 当前模块为什么必须存在，它处理的是哪一个尚未解决的约束？
2. 为什么选择这一结构或算子，它的机制与问题特性如何对应？
3. 数据、状态或监督信号如何从输入变为输出？
4. 该设计带来什么可由机制或证据支持的收益？
5. 输出如何进入下一模块，或当前模块留下了什么问题需要下一模块处理？

本文使用三级规则：

- **必须**：缺失后会造成方法契约不闭合、不可复现或模块关系误读。
- **应当**：四篇本地参考学位论文反复出现、且有助于降低阅读成本的推荐模式。
- **可以**：由方法规模、学科惯例和导师要求决定的组织选择。

本地参考论文只用于比较结构，不作为正文措辞或学术主张的直接来源。

## 2. 方法节的总体顺序

多模块方法节应当按下列顺序展开：

```text
问题与数据契约
  -> 总体数据流和模块分工
  -> 模块 A：解决基础约束
  -> 模块 B：处理 A 的输出或剩余约束
  -> 模块 C：完成融合、校准、决策或监督
  -> 训练/推理流程与最终输出
  -> 实验验证对象
```

总体介绍必须先给出模块关系，再进入局部公式。至少说明：共同输入、各模块输出、执行顺序、
训练与推理差异，以及最终输出由哪个模块产生。框架图、正文、公式和伪代码必须使用同一数据流。

可以保留承担独立技术单元的 `\subsection` 或 `\subsubsection`。不要为每个操作设置
`\paragraph{}` 式行内小标题，再在标题后重复"本模块主要用于……"。标题只负责导航，正文仍须
完成因果和接口衔接。

## 3. 单个模块的叙述契约

每个核心模块必须覆盖以下角色。一个角色可占一句或一段，不要求机械套用固定句式。

| 角色 | 必答内容 | 典型问题 |
| --- | --- | --- |
| 当前约束 | 上游结果还缺什么，或原始数据有什么性质 | 为什么不能直接进入下一步？ |
| 所需能力 | 为消除该约束，算子需要具备什么能力 | 需要对齐、筛选、融合、校准还是反馈？ |
| 设计选择 | 所选机制如何提供该能力 | 为什么是门控、注意力、扩散或约束优化？ |
| 处理过程 | 输入经过哪些关键变换 | 计算顺序、张量/集合变化和状态更新是什么？ |
| 输出对象 | 模块准确产出什么 | 输出的名称、形状、语义和有效范围是什么？ |
| 下游接口 | 输出如何被下一模块使用，或还剩什么约束 | 两个模块通过什么关系连接？ |

推荐的自然段骨架是：

```text
由于〈当前输入/上游输出〉仍存在〈约束〉，后续〈任务〉不能直接进行。
为获得〈所需能力〉，本节采用〈设计〉；其中〈机制〉使其能够〈机制级作用〉。
给定〈输入〉，模型依次执行〈关键变换〉并得到〈输出〉。
该输出作为〈下一模块的输入/监督/约束〉；但〈剩余问题〉仍需由下一模块处理。
```

方法选择的理由应短而具体。标准方法不必重写教科书原理，应说明"如何用于本问题"以及任何
修改；可能引起质疑的选择必须说明依据。MIT EECS Communication Lab 将这类理由概括为支撑
方法正确性的"最低必要论证"，同时要求交代选择该方法的目的和适用性。

## 4. 相邻模块的连接必须显式化

对每一对相邻模块，必须写清三个对象：**上游产出、连接变换、下游用途**。重构前建议填写：

| 上游模块 | 上游产出 | 连接类型 | 中间变换 | 下游模块如何使用 |
| --- | --- | --- | --- | --- |
| A | `z_A` | 串行数据 | 对齐/投影 | B 的直接输入 |
| B | 候选集合 | 校准准入 | 阈值与预算筛选 | C 的监督样本 |

常见连接类型如下：

| 连接类型 | 判据 | 建议表述重点 |
| --- | --- | --- |
| 串行数据连接 | A 的输出直接成为 B 的输入 | 名称、形状、语义是否保持或改变 |
| 并行表征连接 | A、B 共享输入并分别提取表征 | 在何处、按何种规则融合 |
| 监督/目标连接 | A 产生标签、区间、权重、损失或约束 | 信号如何进入 B 的目标函数 |
| 校准/选择连接 | A 产生候选，B 决定准入或排序 | 候选不能等同于训练样本或最终输出 |
| 反馈/控制连接 | 下游评价返回上游更新 | 反馈量、更新对象和停止条件 |
| 剩余约束连接 | A 解决一部分问题，但暴露新的限制 | 用该限制引出 B，而不是机械报幕 |

若两个模块没有直接数据依赖，必须主动排除容易产生的误解。例如：

```text
B 不使用 A 的预测结果作为条件；二者共享同一输入语义，并通过 C 构造的监督关系相接。
```

禁止只写"在 A 之后加入 B"或"接下来介绍 B"。这类顺序词只说明排版次序，没有说明技术关系。

## 5. 公式、图与算法应嵌入论证

公式不能替代叙述。每个关键公式应形成以下闭环：

```text
公式前：说明为什么需要该计算、输入对象是什么
公式：给出变换、目标或约束
公式后：解释新符号、输出语义及其下游用途
```

必须遵守：

- 张量、集合、时间窗口、掩码和标签在首次使用时给出外部语义；内部转置或投影另行说明。
- 公式顺序应与实际计算顺序一致；若为便于推导而改变顺序，必须明示。
- 公式后不只列"式中"释义，还要说明该式解决了哪一项约束、产生了什么对象。
- 总体框架图负责全局数据流，模块图负责局部变换；正文必须引用图中关键边，而非只说"如图所示"。
- 伪代码的输入、冻结/更新对象、循环顺序、停止条件和输出必须与正文一致。

## 6. 设计收益与实验证据分级

方法段可以陈述由定义或结构直接推出的**机制级作用**，但不能提前写成未经验证的性能结论。

| 表述 | 证据要求 | 示例 |
| --- | --- | --- |
| 定义事实 | 公式或算法即可 | "掩码为零时，条件分支不参与融合。" |
| 机制级作用 | 结构、复杂度或逻辑推导 | "该回退路径保持条件缺失时的数据流闭合。" |
| 经验性能 | 实验、消融或可靠引用 | "该模块提高预测精度。" |
| 因果归因 | 区分性实验或理论证明 | "性能提升主要来自该模块。" |

"有利于""增强""提高""有效解决"等词不能代替证据。若只有设计依据，应改为"用于""使得""在
定义上保证"或"为后续……提供"。若实验尚未验证模块贡献，不得写"本章进行了改进，因此性能
更好"。

## 7. 可复现信息的最小集合

IEEE Author Center、Nature 和 PLOS 均把可复现性作为方法部分的核心要求。学位论文的方法描述
至少应明确：

- 输入来源、样本单位、形状、时间语义和预处理；
- 标准化、划分、拟合或校准对象来自哪个数据块，避免信息泄漏；
- 关键参数、阈值和超参数的取值或确定方式；
- 模块的训练顺序，哪些对象更新、冻结或只在推理期使用；
- 随机过程、候选生成、筛选、停止条件和失败/回退路径；
- 输出的类型、范围、单位及下游消费者；
- 标准方法的原始来源，以及相对标准方法的新增或修改。

细节应"足以解释和复现，但不堆积无关操作"。Nature 明确要求方法部分简洁，同时包含解释和
复现结果所需的全部要素；已发表标准方法可引用，但新增或变体必须展开说明。

## 8. 段落与标题的使用

- 一个自然段承载一个主要推进关系，不把"动机、输入、结构、优点"拆成互不相连的标签段。
- 段首优先承接当前约束或上游对象；段末优先给出输出、作用或下一步接口。
- 连接词必须对应真实关系。因果用"因此/由此"，限制用"但/仍"，数据继承用"给定/基于"，
  不能用"首先/其次/最后"掩盖关系缺失。
- 小标题可以组织独立技术单元。MIT 的方法写作指南同样建议用小标题建立逻辑流，但小标题不能
  替代段落间的语义连接。
- 当某个"模块"只有一两句定义、没有独立输入输出或推导时，应并入相邻自然段，不单设标题。

## 9. 正反例

### 不合格：标题报幕

```text
动态编码模块。本模块用于提取动态特征。
扩散模块。本模块用于生成样本。
筛选模块。本模块用于筛选高质量样本。
```

问题：只有职责清单，没有问题来源、设计理由、输入输出和模块连接。

### 基础合格：有数据流但缺递进原因

```text
A 输出动态特征，B 以该特征为条件生成候选，C 对候选进行筛选。
```

问题：说明了顺序，但未解释为何需要 B、候选为何不能直接使用，以及 C 的准入依据。

### 推荐：约束驱动的连续叙述

```text
A 得到的基础表征仍受原始样本覆盖范围限制，不能补充稀疏区域。为扩展该区域的候选支撑，
B 复用相同输入语义，并以 A 之外的指定条件生成候选。生成条件不等同于可信监督，因此候选
不能直接进入学生训练。C 随后利用独立校准对象将候选转换为带区间和权重的监督样本，最终
由学生模型输出任务结果。
```

优点：相邻模块由"剩余约束"和"监督接口"连接，同时排除了错误的数据依赖解释。

## 10. 审阅与改写流程

1. 锁定事实边界：保护符号、公式、引用、数值、数据划分和已有实验结论。
2. 画出模块图：为每个节点填写输入、处理、输出、训练状态和失败/回退路径。
3. 填写相邻模块接口表：逐边确定连接类型、变换和下游用途。
4. 先重写总体数据流和模块过渡，再整理模块内部句子，最后调整标题。
5. 逐式检查"目的 -> 公式 -> 解释 -> 下游用途"是否闭合。
6. 将收益表述按"定义事实/机制作用/经验性能/因果归因"分级，删除证据越界。
7. 只读每个模块的首段和末段；若仍无法复述整条方法链，说明过渡尚未闭合。

## 11. 验收清单

| 编号 | 检查点 | 等级 |
| --- | --- | --- |
| M-MOTIVE | 每个核心模块均由当前约束或上游剩余问题引出 | 必须 |
| M-RATIONALE | 设计选择与所需能力之间存在可解释对应 | 必须 |
| M-IO | 输入、关键变换和输出语义闭合 | 必须 |
| M-EDGE | 每对相邻模块明确上游产出、连接变换和下游用途 | 必须 |
| M-NONDIRECT | 非直接依赖关系已排除可能误解 | 必须 |
| M-EQUATION | 关键公式具有目的说明、符号解释和下游用途 | 必须 |
| M-EVIDENCE | 性能和因果归因未超出实验或理论证据 | 必须 |
| M-REPRO | 训练/推理、参数来源、冻结对象和回退路径可复现 | 必须 |
| M-HEADING | 标题承担导航而非代替逻辑连接 | 应当 |
| M-CLOSURE | 方法末段给出最终输出并自然进入实验验证 | 应当 |

## 12. 来源与适用边界

### 网络一手资料

- MIT EECS Communication Lab, [Paper: Methods (EE)](https://mitcommlab.mit.edu/eecs/commkit/journal-article-methods-ee/):
  方法部分应给出复现所需细节，以最低必要论证说明方法选择，并用小标题建立逻辑流。
- IEEE Author Center, [Structure Your Article](https://journals.ieeeauthorcenter.ieee.org/create-your-ieee-journal-article/create-the-text-of-your-article/structure-your-article/):
  方法部分应直接说明做了什么、如何完成；足够详细的方法使研究可复现并便于他人信任和扩展。
- Nature, [Formatting Guide](https://www.nature.com/nature/for-authors/formatting-guide):
  方法部分应尽可能简洁，同时包含解释和复现结果所需的全部要素；标准方法可引用，新增或变体需说明。
- PLOS ONE, [Submission Guidelines](https://journals.plos.org/plosone/s/submission-guidelines):
  统计和分析方法应提供复现所需的技术细节，包括软件版本、预处理、异常值和缺失数据处理等。

### 本地结构对照

- 《水泥粉磨过程关键指标预测模型与运行优化算法研究》3.3.1--3.3.3：以前一模块输出及
  尚存维度差异引出特征融合。
- 《水泥熟料煅烧过程数据增强及质量预测模型研究》5.2--5.3、6.2--6.3：按"问题特性 ->
  并行表征 -> 融合 -> 预测"和"生成/判别/预测信息通路"组织模块。
- 《水泥烧成系统多指标预测模型与决策算法研究》第 3--5 章：先给总体结构，再按输入层、
  特征层、输出层或内外循环展开。
- 《复杂非平稳工业过程异常监测与诊断方法研究》4.3、5.3：用上一通道输出、可信度不足和
  综合评估需求连续引出后续模块。

网络资料提供通用的可复现性和逻辑组织要求；本地论文只提供工业过程中文博士论文的结构惯例。
二者均不能替代导师、本校规范或具体研究证据。
