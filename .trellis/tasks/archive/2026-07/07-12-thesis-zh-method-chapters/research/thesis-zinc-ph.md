## 1. 章式结构

**方法章采用"一章一方法 + 同章仿真验证"模式，而非方法/实验分章。** 第3/4/5章各聚焦技术链的一环（pH估计 / 工况识别 / 多工况控制），每章末尾都有一节独立的"XX仿真验证"（3.4/4.4/5.4）+"本章小结"（3.5/4.5/5.5）。

**结论前确有独立的工程应用/系统实现章（第6章）**，标题"中性浸出过程智能调控系统及工业应用"，把前三章方法集成落地，并给出真实工业现场上线验证。这是本论文"工程应用"特色的核心承载章。证据：第6章开篇"本章从中性浸出过程智能调控系统的需求分析出发，建立了智能调控系统架构。然后，基于系统架构和前述pH在线估计方法、工况智能识别方法、pH稳定控制方法进行了功能实现和应用"（L7195-7197）。

**关键分工**：第3/4/5章的"仿真验证"用的是历史数据 / 仿真被控对象（离线验证方法本身），第6章才给"现场应用效果"（上线前后对比、真实生产指标）。即"方法有效性"与"工程落地有效性"分层验证。

## 2. 章内骨架

方法章节序列高度规整，典型为 **章引言（无节号，紧跟章标题）→ 框架/定义节 → 方法节（1~2个）→ 仿真验证节 → 本章小结**：

- **第3章**：3.1 机理模型构建（含 3.1.1 建模、3.1.2 参数辨识）→ 3.2 数据模型（模糊神经网络）→ 3.3 融合方法 → 3.4 仿真验证 → 3.5 小结。直属节 5 个。
- **第4章**：4.1 工况定义与识别框架（4.1.1 定义、4.1.2 框架）→ 4.2 监测方法（4.2.1 **AE与LSTM方法介绍**基础知识、4.2.2 监测）→ 4.3 精细划分方法 → 4.4 仿真验证 → 4.5 小结。直属节 5 个。
- **第5章**：5.1 控制框架 → 5.2 稳态规则提取控制 → 5.3 非稳态操作模式控制（5.3.1 离线库、5.3.2 在线匹配）→ 5.4 仿真验证 → 5.5 小结。直属节 5 个。
- **第6章**：6.1 需求分析与架构（6.1.1 需求、6.1.2 架构）→ 6.2 软件实现（6.2.1 智能调控功能、6.2.2 其他功能）→ 6.3 现场应用效果与分析 → 6.4 小结。直属节 4 个。

**命名习惯**：方法节统一"基于X的中性浸出过程Y方法"；每章仿真节统一"中性浸出过程XX仿真验证"；小结统一"本章小结"。直属节数量稳定在 4~5 个，二级子节最多再拆一层（X.Y.Z），不再深。

**反直觉**：第4章 4.2.1"AE与LSTM方法介绍"是一个**独立的预备知识/基础理论子节**，把要用到的通用模型（AE、LSTM）先介绍一遍再进入自研方法（4.2.2）。方法章内部允许放"教科书式基础知识节"，并非直接进自研内容。

## 3. 章引言（承上启下）

**每个方法章标题后紧跟一段无节号章引言**（约 2~3 段，300~500 字），套路稳定为"**工艺背景 → 问题/难点 → 已有手段局限 → 本章提出什么 → 为后续哪章打基础**"：

- 第3章引言（L1726-1748）：介绍5个浸出槽工艺→pH难在线检测（人工化验时滞）→机理模型/数据模型两条路径各自局限→"本文提出了机理与数据融合的中性浸出过程pH在线估计方法…**为后续的工况识别与pH值控制打下基础**"。
- 第4章引言（L3643-3665）：入口来料波动→数据时空分布特性→"**本章提出了基于时空堆栈自编码的…工况识别框架与方法**"。
- 第5章引言（L5312-5322）：**显式承接第四章**——"**在前面第四章中**，从现场实际情况以及精细化管控的角度出发，分析并定义了…非稳态工况以及…稳态工况，并实现了非稳态工况的监测与稳态工况的精细化划分"（L5317-5319）。
- 第6章引言（L7186-7200）：工艺承上启下地位→pH稳定控制困难→"某大型锌冶炼厂在转型升级过程中亟需一套…智能调控系统"→本章从需求分析出发。

**规律**：章引言**显式承接前章结论**（用"第X章""前面第四章"等字样，第5、6章最明显）并**预告本章框架而非逐节罗列**——预告的是"提出什么框架/方法"，不是逐节点名（逐节预告放在每节开头的引导句）。字数 2~3 段。

## 4. 方法部分写法

- **有独立的问题形式化/数学描述节**：第3章 3.1 是完整的机理数学建模，从化学反应方程（式3-1）→假设条件（4条，L1808-1813）→物料守恒平衡式（式3-2）→阿伦尼乌斯反应系数（式3-3）→有效基质表面积推导（式3-4~3-5）。**公式密度高**：仅第3章就到式(3-30)，第4章到式(4-28)，第5章到式(5-41)。
- **假设条件显式列举**："任何机理模型的建立均需要设定假设条件。本节…做出以下假设：1）…2）…3）…4）…"（L1807-1813）——机理建模先摆假设是固定动作。
- **算法/步骤用带圈序号或（1）（2）分点**：如4.1.2框架分"（1）基于时空堆栈自编码的稳态/非稳态工况监测""（2）基于高斯混合模型的稳态工况精细划分"（L3725、L3744），每点用整段散文描述数据流与判定逻辑，**未见严格 LaTeX algorithm 伪代码环境**，而是"训练→提取特征→重构→与阈值比较→判定"式流程叙述（L3738-3743）。
- **有方法总体结构图**：每个方法章第一节都配一张框架图——图4-1"工况识别框架"（L3808）、图5-1"多工况pH稳定控制框架"（L5388）。
- **呼应总体框架（第2章）与前序章**：第5章 5.1 框架节的"（1）"环节直接调用"**通过第三章的pH在线估计方法**为稳定控制过程提供关键实时信息…**采用第四章提出的…工况识别方法**"（L5356-5359）。方法章之间通过"第X章的方法提供输入"显式串成技术链。

**关键写法规律**：

1. **仿真节开头先复述"为验证本章所提方法的有效性"**，再交代数据（三章开头句式几乎一致：L3446、L5115、L6915-6918）。
2. **结果分析走"描述现象 → 对比方法 → 归因"三段式**，归因高频用"**这是因为…**/**其主要原因在于…**"。例：第4章"与普通堆栈AE相比，增强型…FAR降低了68%，FDR提升了6%…**这是因为**中性浸出过程数据时空分布…堆栈AE只实现了单一维度的特征提取"（L5236-5240）；第5章"这是因为当工况发生变化时PID之前整定的参数难以适用"（L7088-7089）。
3. **分析文字与表格数字紧密呼应**，直接引表中数值并给相对提升幅度（"降低了68%""提升4.4%""浸出率提高2.8%"）。
4. **指标以点估计值呈现，未见均值±方差写法，也未见显著性检验**（t检验/p值等统计检验缺席）。表格给单点数值（如 RMSE 0.0824），最优值加粗与否因 PDF 抽取无法确证，但正文明确"融合模型取得了最好的…效果"。
5. **多工况/鲁棒性验证体现在"稳态+非稳态两方面分别验证"**（每个控制/识别章都拆稳态、非稳态两组实验，L5185-5186、L6916-6918）。

## 6. 本章小结

**模板高度统一**，长度约 1 段 150~250 字，套路为"**针对什么问题 → 本章提出了什么 → 首先…然后…最后… → 效果/为后续哪章奠定基础**"：

- 第3章小结（L3628-3637）："为解决…问题，本章提出了…。首先…然后…最后…。通过上述pH在线估计的研究，**为后续第四章工况识别、第五章pH控制提供了关键实时信息**。"
- 第4章小结（L3290-3306）：同结构，收尾"**为后续在不同工况下采用不同的控制策略打下了基础**"。
- 第5章小结（L7168-）：同结构。
- 第6章小结（L7596-7604）：略不同——收在量化成效上"pH稳定性控制指标提升了4.4%，浸出率提升了2.8%…具有一定的推广应用价值"。

**规律**：方法章小结**必含"为第X章奠定基础"式启下句**（启下明确指向下一技术环节）；工程应用章（第6章）小结改为收束到量化效益+推广价值，不再启下。

## 8. 第6章工程应用章的组织方式（重点特色）

这是本论文"工程应用"标签的核心，写法值得单列：

1. **需求分析先行（6.1.1）**：分"功能性需求"（pH在线估计/工况识别/pH稳定控制/其他功能）与"非功能性需求"（安全性/实用性/可维护性可扩展性），每条从"现场调研发现…"出发，**大量引用作者一线经验**（"基于作者长期以来的工作经验"L7208-7209）。
2. **系统架构分层描述（6.1.2）**：设备层→DCS层→数据中转层→智能调控层四层，配架构图6-1；**披露真实技术栈**：Visual Studio + C# Winform，Python/MATLAB 算法构件打包 DLL，SQL Server，OPC Data Access 协议，浙江中控 ECS-700 DCS，甚至给硬件配置表（表6-1 戴尔服务器型号）。
3. **软件实现（6.2）**：逐功能模块叙述实现，**配大量系统界面截图**（图6-3~6-8）。把前三章方法如何落成软件构件讲清（"将基于机理与数据融合的…方法进行算法构件研发…部署于智能调控系统中"L7342-7345）。
4. **现场应用效果（6.3）——真实工业验证的核心**：
   - **三阶段渐进上线**：离线方案验证（Matlab仿真对象）→半自动控制（只上pH控制、人工输pH）→全自动（估计+控制全接入）。体现"流程工业不能直接拿生产对象试错"的工程审慎（L7502-7504）。
   - **上线前后对比量化**：表6-2/6-3 给 pH 稳定达标率 91.7%→96.1%（提升4.4%），浸出率 81.6%→84.4%（提升2.8%），铁离子达标率提升3.1%。
   - **数据脱敏声明**："出于该企业对生产过程关键信息保密的要求，对展示的数据以及生产指标进行了缩放和脱敏"（L7493-7494）——工业论文标准做法。
   - **给出稳定运行时间背书**："智能调控系统自2020年10月以来长期在生产现场运行"（L7563-7564）。

## 9. 反直觉点汇总（与"直觉上应该这么写"不符的实际惯例）

1. **方法有效性验证与工程落地验证分层、分章**：第3/4/5章的"仿真验证"只证方法本身（离线数据/仿真被控对象），真正的工业现场上线验证集中到第6章，不在方法章硬塞现场数据。直觉上会把"现场验证"放进各方法章，实际是攒到应用章统一交付。
2. **方法章内允许独立"基础知识介绍"子节**（4.2.1 AE与LSTM介绍），不怕被认为"像教材"。
3. **控制章的仿真不是真·闭环上线，而是先用生产数据拟合一个 NARX 模型当"被控对象"再控制它**（L7002-7006），并明确说明"流程工业不能直接拿生产对象测试"。这是过程控制博士论文的通行安全逻辑。
4. **实验几乎不做统计显著性检验、不写均值±方差**，用单点指标值+相对提升百分比即完成论证；工业论文更看重"达标率""浸出率"等业务指标而非统计严谨性。
5. **第6章大篇幅写软件工程细节**（技术栈、界面、硬件配置、DCS 型号、三阶段上线流程），这些在"纯算法"论文里通常被略去，但正是工程应用型博士论文的加分与答辩护城河。
6. **章引言/小结显式点名前后章号**（"第三章…第四章…第五章"），章间强耦合成"估计→识别→控制→系统"技术链，不回避"承上启下"的直白措辞。
