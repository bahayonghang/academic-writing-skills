# 工作流程和最佳实践

选择适合用户要求的最小模块序列。

## 常见的审核路径

1. 构建/调试路径：
   `compile` -> `bibliography`
2. 散文品质之路：
   `grammar` -> `sentences` -> `logic`
3. 提交卫生路径：
   `format` -> `figures` -> `title`
4. 语言清理路径：
   `translation`或者`deai`， 然后`expression`如果还需要色调抛光
5. 实验考察路径：
`experiment` 本身，除非用户还要求逻辑或图形审查

## 最佳实践

1. 一次路由到一个关注点，而不是默认调用每个模块。
2. 保存`\cite{}`, `\ref{}`, `\label{}`、数学和自定义宏，除非明确要求进行编辑。
3. 将脚本输出视为原始分析；将其转换为简洁的 LaTeX 友好的结果作为最终响应。
4. 当用户在审阅阶段后要求进行源代码编辑时，请使用版本控制。

## 修改顺序（逻辑→句子→词汇，不要颠倒）

当请求需要多个抛光通道时，请按此顺序应用更改并执行
不反转它：

1. **论证/逻辑** — 段落顺序、缺失或重复的主要信息、章节转换。
2. **句子结构**——分割>40字的句子，被动→主动，前置高信息内容。
3. **词汇/格式** — AI 语气单词、数字/单位格式、破折号与连字符、首字母缩略词一致性。

为什么顺序被固定：在固定之前润色句子的措辞（步骤 3）
当步骤 1 稍后删除或合并该结构（步骤 1）时，就会浪费精力
段落。由粗到细效率提高数倍。
