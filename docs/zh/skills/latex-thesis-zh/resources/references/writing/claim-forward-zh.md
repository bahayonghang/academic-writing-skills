# 主张前置写作指南（claim-forward）

如何让读者先读到主张、再读到限制，且不删除任何一条限制或不利结果。配合 `claim-forward` 模块（`references/modules/claim-forward.md`）与 `references/writing/over-claim-guard.md` 的"向上校准"节使用。

## 唯一规则

**主张在前，范围在后，限制只写一次。** 每个承载贡献的段落以贡献开头。范围（主张覆盖什么）以肯定形式紧随其后。每条限制只写一次，写在读者预期的位置（设计约束写在方法章，证据边界写在讨论或"本文的不足"小节），不在每个主张前重复为 hedge。

## 本指南不允许的改法

以下改法被有意否决。它们与过度声明防线（"校准而非胆怯"，绝不为显得果断而删 caveat）、主张—证据契约以及审稿侧的挑选式呈现检查相冲突：

- 删除不利对比、失败设置或非主线结果。
- 把技术缺陷改写成"范围选择"（方法在长序列上失效却写成"本文不针对长序列"）。
- 挑选基线或指标使论文"不可能输"。
- 把动词抬到证据未支撑的那一级（见过度声明防线中的确定性阶梯）。

claim-forward 只改**顺序与措辞**。内容不变。

## 句子功能（改前先分类）

| 功能   | 判定                                                     | 应在位置                                                 |
| ------ | -------------------------------------------------------- | -------------------------------------------------------- |
| 主张   | 陈述本文取得了什么，可带数字也可不带                     | 段首                                                     |
| 证据   | 指向表、图、统计量或对比                                 | 紧跟主张                                                 |
| 范围   | 用肯定形式说明主张覆盖什么（"在三个室内基准上"）         | 主张句内或紧随其后                                       |
| 限制   | 说明主张不覆盖什么或在哪里失效                           | 主张之后；每条一次；或写在"本文的不足"小节               |
| 过渡   | 连接下一段                                               | 段末                                                     |
| 过程   | 叙述作者尝试过什么、何时尝试                             | 通常从实验结果中删除；读者需复现时写在方法章             |

## 五步改写

1. **定位主张。** 找到陈述贡献的那一句。若没有，该段先需要一句主张，再做其他修改（不得编造；询问作者）。
2. **主张前置。** 把它放到段内任何免责、道歉或限制之前。
3. **范围转肯定。** "本文不处理室外场景"改为附在主张上的"在三个室内基准上"。仅当肯定式范围已承载同样信息时才删除否定句；否则保留在主张之后。
4. **每条限制只放一处。** 若同一 caveat 出现在摘要、绪论和实验结果，保留在证据被讨论之处及"本文的不足"小节存在之处。要删的是其他副本，不是限制本身。
5. **最小修改并复查。** 重读：每个数字、对比、caveat 是否都还在？是否有动词高于其证据等级？若有，退回去。

## 推荐与不推荐的写法

| 不推荐                                                                     | 推荐                                                                                                     | 原因                                              |
| -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| "本文不试图解决通用场景理解问题。本文方法将准确率提高 12%。"               | "本文方法在三个室内基准上将准确率提高 12%。本文未评估室外场景。"                                         | 主张在前；范围肯定；边界保留                      |
| "遗憾的是，本文方法在长尾划分上仍明显落后于理想上界。"                     | "本文方法在长尾划分上落后理想上界 4.1 个百分点。"                                                        | 把差距写成测量值，不写成道歉                      |
| "尽管评估范围限于一个数据集，本文取得 7% 的提升。"                         | "本文在数据集 X 上取得 7% 的提升。更多数据集上的评估是后续工作。"                                        | 限制在主张之后，且给出方向                        |
| "本文方法可能在一定程度上或许能够提升鲁棒性。"                             | "本文方法在遮挡条件下提升鲁棒性（表 3）。"若证据弱则"本文方法可能在遮挡条件下提升鲁棒性。"               | 只留一个 hedge，由证据决定                        |
| "本文方法仅能达到 91%，仅仅与基线持平。"                                   | "本文方法达到 91%，与基线持平而计算量为其三分之一。"                                                     | 报数字和权衡，不用"仅能 / 仅仅"                   |
| "起初尝试 Transformer 失败，随后改用 CNN 也失败，最终 …"                   | "本文采用混合编码器（3.2 节）；附录 B 报告评估过的备选方案。"                                            | 过程编年移出实验结果（`CF-LOSS-FRAME`）           |
| 结论收尾："然而，该框架无法处理帧率可变的输入。"                           | "… 尚不支持帧率可变的输入；将缓冲机制扩展到异步输入是下一步工作。"                                       | 以方向收尾，保留判定                              |

## 自查（改完后回答四个问题）

1. 每个贡献段的首句是不是主张？
2. 每条限制是否都在它限定的主张之后，且只出现一次？
3. 每个"遗憾的是 / 仅仅 / 仅能 / 未能 / 效果有限 / 存在严重不足"是否都换成了测量值或肯定式范围？
4. 结论末段最后一条限制之后是否加了方向，而不是新的自我否定？

若回答任一问题时删除了对比、结果或 caveat，撤销该修改。

| `CF-LOSS-FRAME`  | 仅 `[LLM]`   | 把过程编年移出实验结果 / 结论；备选方案保留在方法章或附录                    |

## 与结论章模块的关系

`conclusion` 模块的 `CC-OUTLOOK-TRANS` 要求展望前有承接句（"上述不足有待后续工作 …"），`CF-CLOSE-NEG` 要求负面判定后有方向。两者同时满足的写法：负面判定 → 承接句 → 展望；`references/writing/conclusion-guide-zh.md` 的展望段模板已符合。不要为满足 claim-forward 把结论末段的限制删掉——那会同时触发结论章指南的"限制缺失"。

## 与过度声明防线的关系

过度声明防线向下校准（证据弱于措辞）。claim-forward 向上校准（措辞弱于证据）。两者共用同一阶梯：claim-forward 改写只能把动词抬到证据已支撑的那一级，防线的"反向校准"清单列出了强表达被认可的情形。拿不准时，动词不动，只改顺序。

## 防御性说明的三类处置（仅 LLM）

这三类只由 LLM 判断。不新增观察码，不建词表，也不删除不利结果。强度上限仍见上文与过度声明防线的关系。未验证的弱点不得写成设计优点。

### 保留真实证据边界

范围：删掉以后，方法合法性或证据层级会被追问。
可保留：本文只报告离线回放窗口内的误差，不把该误差写成闭环控制收益。
不可改：删掉该句，只留“本文降低了控制误差”。

### 否定转为正面陈述

范围：仅当原文已经支持正面说法，才把否定改成正面。区分必须还在。
可保留：归一化阈值用于初筛。硬件限值由部署环境单独给定。
不可改：把“不将归一化阈值等同于硬件限值”改成“归一化阈值保证硬件安全”。

### 弱点写成取舍

范围：仅当稿件已经把它写成真实设计选择，才把弱点写成取舍。
可保留：峰值通道的极值误差大于基线。稿件已写明该通道在均方误差下输出分组均值，极值保真不是本设计的目标。
不可改：峰值被低估，因而写成“有效抑制数值抖动并保持单调”。未验证的弱点不得写成设计优点。误检率高于基线必须留下，不得删除，也不得写成“因此更保真”。

### 比喻词只是语境例子

门禁、筑牢、本质安全、理论性能上界不是禁词正则。上下文若已经写明校验、阻断或回退，就按那个可观察机制写。不得据此编制禁用词表。
