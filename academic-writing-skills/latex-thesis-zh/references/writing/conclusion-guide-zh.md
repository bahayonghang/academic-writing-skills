# 结论章（总结与展望）写作专章指南

面向中文博士/硕士学位论文的**结论章**写作与诊断。此处的结论章特指正文末、参考文献之前
的独立章，标题多为"结论""结论与展望""总结与展望"三者之一。诊断入口：

```bash
uv run python $SKILL_DIR/scripts/analyze_conclusion.py main.tex
uv run python $SKILL_DIR/scripts/analyze_conclusion.py main.tex --json
```

> 本文所有规律为 5 篇工业背景博士论文（固废焚烧、水泥烧成、水泥熟料、水泥粉磨、锌冶炼浸出）
> 结论章逐篇通读的**学科惯例**口径，样本 3/5 出自燕山大学、方向偏过程工业，规则文案按"最佳
> 实践/建议"表述，**以导师与本校研究生院最新规范为准**。仅 ≥4/5 的规律作默认告警，2~3/5 的
> 规律只作 Info/建议级。

## 结论章整体结构模板

结论章推荐采用**扁平三段式**（5/5 均无需子节号，直接用开篇段 + 编号贡献列表 + 展望列表）：

```text
① 开篇承上式总述：复述研究问题，用"首先……其次……最后……"串起全文研究链
② "……如下："导语 + 编号贡献条 (1)(2)(3)[(4)]（3~4 条）
③ 局限/承接过渡句（"仍存在一定不足""仍然有很多问题悬而未决"）
④ 展望 2~3 条：具体技术研究方向
```

| 区块 | 职能 | 篇幅参考 |
| --- | --- | --- |
| 开篇承上式总述 | 复述问题 + 研究链，引出分条 | 1 段 |
| 编号贡献条 | 按技术贡献/章重组（非逐章复述），3~4 条 | 主体，占比最大 |
| 承接过渡句 | 承认局限，挂钩展望 | 1~2 句 |
| 展望 | 2~3 条具体技术方向 | 总结:展望约 2:1~3:1 |

全章 **2~4 页**，约占正文 1.5%~3.3%。总结篇幅应大于展望（5/5，约 2:1~3:1）。

## 开篇承上式总述（CC-OPEN）

开篇一段先复述研究问题与全文研究链，用序词把各章工作串成一条线，再引出分条。序词
（首先/其次/然后/再次/最后）**至少 2 个**方能体现研究链，否则只作 Info 提示。

正例句式（改写自范文摘录，勿照抄）：

```text
本文针对〈对象〉在〈场景〉下的〈瓶颈〉问题，开展了〈研究主题〉研究。首先，……；其次，
……；最后，……。取得的主要创新性工作如下：
```

## 贡献条骨架（CC-SKELETON / CC-ENUM）

贡献主体以带序号列表 (1)(2)(3)[(4)] 呈现，条数落在 **3~4**（超出只提示）。列表前须有一句
"……如下："导语，导语用词可为"主要创新性工作/具体创新工作/主要结论/所取得的成果"等。

每条贡献遵循骨架"**针对……问题，提出/建立/设计了……方法/模型，实验/应用（结果）
表明/验证了……**"。骨架句式变体较多，脚本只做粗筛计数，语义完整性交 [LLM] 复核。

| 写法 | 判定 |
| --- | --- |
| "（1）针对高维数据不平衡问题，建立了单调有界对抗学习的数据增强模型，利用生产数据验证了其一致性。" | 通过（针对-方法-验证三要素齐备） |
| "（1）本文研究了数据增强。" | 缺陷（无问题导向、无验证载体，CC-SKELETON [LLM] 提示补全） |
| 贡献散文成段、无 (1)(2) 编号 | Info（CC-ENUM 提示改为编号列举） |

贡献按**技术贡献/章**组织（每条 = 一项方法/模型/一章工作），不按摘要要点另行拆分。

## 展望写作（CC-OUTLOOK-*）

展望须为**具体技术研究方向**，反例是空话套话。以下为空话黑名单（词表文件化，维护节律对齐
deai 词表约定，见脚本 `OUTLOOK_EMPTY_PHRASES`）：

- "广阔前景""值得进一步研究""有待深入""进一步完善本方法""继续深入研究"

判定规则：黑名单命中且**同句无具体技术名词**才报 Warning（CC-OUTLOOK-EMPTY）；若空话出现
在具体方向句尾（如"……的焙砂添加量优化调度值得进一步研究"），因同句有技术名词，不误报。

其余展望规范（均 Info 级）：

- **CC-OUTLOOK-TRANS**：展望前有一句局限/承接过渡句（"仍存在一定不足""仍然存在问题值得
  进一步深入研究""仍然有很多问题悬而未决"）。最优雅者显式列出本文局限再逐条对应展望。
- **CC-OUTLOOK-COUNT**：展望条数落在 **2~3** 条（超出只提示；成段式无编号展望不强制）。
- 展望句用未来向措辞（"下一步……""未来可……""将是下一步需要考虑的问题"）。

正例（改写自范文）：

```text
然而，所提方法在更复杂工况下的泛化能力、工业现场可部署性仍存在一定不足。因此，未来
研究可从以下两方面深入：（1）物理与数据混合驱动的建模方法……；（2）面向 PLC/DCS 的
工程部署与在线适配……。
```

## 篇幅比与结构风格（CC-RATIO / CC-SUBSEC）

- **CC-RATIO**（Info）：总结:展望字符比落在 1.5:1~4:1 之外才提示；总结应显著长于展望。
- **CC-SUBSEC**（Info）：是否设子节号（X.1 总结 / X.2 展望）与是否编号为"第 X 章"均为
  **风格选择**——5 篇中仅 1/5 设子节号、3/5 为编号章。检查器**只在检测到时给"与全文风格
  保持一致"提示，不判对错**，不要求结论章必须有子节。

## 数值一致性（CC-QUANT）

结论**不强制带数值**（5 篇中仅 1/5 在结论内密集重述百分比，4/5 保持定性收口）。但**一旦
重述数值，须与正文/摘要一致**：脚本抽取结论中的百分比/小数指标 token，逐个在正文可见文本中
查存在性；查不到时出 NEEDS-LLM 软提示（不硬报），供人工复核是否为笔误或口径漂移。

## 结论 ≠ 摘要（CC-VERBATIM）

开篇总述与分条应是摘要的**改写复述**（句式重组、补足连接词），**不得逐字复制摘要**。脚本
用 difflib 逐句比对结论与中文摘要，ratio ≥ 0.85 记命中；命中句占结论句 ≥30% 报 Warning，
单句命中列 Info 明细。语义级近义改写交 [LLM] 复核。

## 三段式齐全（CC-TRIAD）

结论须同时含**总结主体 + 创新表述 + 展望**三要素。脚本用词表定位三区块：

- 缺展望或缺总结主体 → **Error**（结构性缺失）；
- 缺创新/成果表述导语 → **Warning**。

## 禁忌清单

| 禁忌 | 检查码 | 级别 | 说明 |
| --- | --- | --- | --- |
| 引入新图表环境（figure/table） | CC-NO-FIG | Error | 结论只以文字重述已有图表数据，不新插图表（5/5） |
| 引入正文未见的新概念/新方法名 | CC-NEW-CONCEPT | Warning（[LLM]） | 分条方法名须为正文各章已定义术语 |
| 引入新文献（`\cite`） | 由 spec-check 承担 | — | 结论禁引用属格式硬规则，本脚本不重复报告 |
| 逐字复制摘要 | CC-VERBATIM | Warning | 见上节 |
| 过度声明（"首次/彻底解决/全面超越"） | 见 over-claim-guard.md | — | 贡献表述有节制、带 hedge；不在本脚本重复实现 |

## 与其他模块的边界

结论章的以下检查**不在本脚本范围**，报告尾注会指路：

- `\cite`、字数上限（≤2000）、模糊措辞（大概/或许）→ 走 `spec-check` 模块
  （`check_spec.py`，见 [../modules/spec-check.md](../modules/spec-check.md)）；
- 过度声明 → 走 [over-claim-guard.md](over-claim-guard.md) 流程；
- 英文摘要时态/AI 腔 → 走 `deai` 模块。

## 分级说明

- 结论章是否编号"第 X 章"（3/5）、是否设子节号（1/5）、是否在结论重述数值（1/5）均为
  **Info 级"与全文风格一致"提示，不设硬规则**（Constraints 1：2~3/5 规律只能做 Info/建议级）。
- "本文/本论文"是合法主语，不列入第一人称禁词；只有"我/我们/笔者"才是口语人称问题。

| CC-OPEN | Script | 首段序词 < 2 个 | Info | C-OPENING 5/5 |

## 输出建议格式

```latex
% 结论章（chapters/conclusion.tex:42）[Severity: Warning] [Priority: P1]: [Script] CC-OUTLOOK-EMPTY 展望第 2 条"具有广阔的应用前景，值得进一步研究"为空话套话且无具体技术名词
% 建议：改为具体技术方向，如"下一步将研究多尺度不平衡数据增强与预测方法"。
```
