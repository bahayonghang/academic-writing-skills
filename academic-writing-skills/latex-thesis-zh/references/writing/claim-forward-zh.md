# 主张前置写作指南（claim-forward）

如何让读者先读到主张、再读到限制，且不删除任何一条限制或不利结果。配合 `claim-forward` 模块（`references/modules/claim-forward.md`）与 `references/writing/over-claim-guard.md` 的"向上校准"节使用。

## 唯一规则

**主张在前，范围在后，限制只写一次。** 每个承载贡献的段落以贡献开头。范围（主张覆盖什么）以肯定形式紧随其后。每条限制只写一次，写在读者预期的位置（设计约束写在方法章，证据边界写在讨论或"本文的不足"小节），不在每个主张前重复为 hedge。

## 本指南不允许的改法

以下改法被有意否决。它们与过度声明防线（"校准而非胆怯"，绝不为显得果断而删 caveat）、主张—证据契约以及审稿侧的挑选式呈现检查相冲突：

- 删除不利对比、失败设置或非主线结果。
- 把技术缺陷改写成"范围选择"（方法在长序列上失效却写成"本文不针对长序列"）。
- 挑选基线或指标使论文"不可能输"。
- 把动词抬到证据未支撑的那一级（见过度声明防线中的确定性阶梯）。

claim-forward 只改**顺序与措辞**。内容不变。

## 句子功能（改前先分类）

| 功能   | 判定                                                     | 应在位置                                                 |
| ------ | -------------------------------------------------------- | -------------------------------------------------------- |
| 主张   | 陈述本文取得了什么，可带数字也可不带                     | 段首                                                     |
| 证据   | 指向表、图、统计量或对比                                 | 紧跟主张                                                 |
| 范围   | 用肯定形式说明主张覆盖什么（"在三个室内基准上"）         | 主张句内或紧随其后                                       |
| 限制   | 说明主张不覆盖什么或在哪里失效                           | 主张之后；每条一次；或写在"本文的不足"小节               |
| 过渡   | 连接下一段                                               | 段末                                                     |
| 过程   | 叙述作者尝试过什么、何时尝试                             | 通常从实验结果中删除；读者需复现时写在方法章             |

## 五步改写

1. **定位主张。** 找到陈述贡献的那一句。若没有，该段先需要一句主张，再做其他修改（不得编造；询问作者）。
2. **主张前置。** 把它放到段内任何免责、道歉或限制之前。
3. **范围转肯定。** "本文不处理室外场景"改为附在主张上的"在三个室内基准上"。仅当肯定式范围已承载同样信息时才删除否定句；否则保留在主张之后。
4. **每条限制只放一处。** 若同一 caveat 出现在摘要、绪论和实验结果，保留在证据被讨论之处及"本文的不足"小节存在之处。要删的是其他副本，不是限制本身。
5. **最小修改并复查。** 重读：每个数字、对比、caveat 是否都还在？是否有动词高于其证据等级？若有，退回去。

**补充：修复顺序。** 五步本身不变。同一段既有过强断言又有模糊让步时（见下文"断言与让步壳共现"），固定按三步处理：① 证据前置，把支撑主张的数字、表图或材料写在前面；② 按 `over-claim-guard.md` 的确定性阶梯校准断言，只降到证据支持的那一级；③ 把模糊让步换成一条带原因的具体边界。只做第 ③ 步会删掉让步而留下过强断言，不得这样改。

## 推荐与不推荐的写法

| 不推荐                                                                     | 推荐                                                                                                     | 原因                                              |
| -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| "本文不试图解决通用场景理解问题。本文方法将准确率提高 12%。"               | "本文方法在三个室内基准上将准确率提高 12%。本文未评估室外场景。"                                         | 主张在前；范围肯定；边界保留                      |
| "遗憾的是，本文方法在长尾划分上仍明显落后于理想上界。"                     | "本文方法在长尾划分上落后理想上界 4.1 个百分点。"                                                        | 把差距写成测量值，不写成道歉                      |
| "尽管评估范围限于一个数据集，本文取得 7% 的提升。"                         | "本文在数据集 X 上取得 7% 的提升。更多数据集上的评估是后续工作。"                                        | 限制在主张之后，且给出方向                        |
| "本文方法可能在一定程度上或许能够提升鲁棒性。"                             | "本文方法在遮挡条件下提升鲁棒性（表 3）。"若证据弱则"本文方法可能在遮挡条件下提升鲁棒性。"               | 只留一个 hedge，由证据决定                        |
| "本文方法仅能达到 91%，仅仅与基线持平。"                                   | "本文方法达到 91%，与基线持平而计算量为其三分之一。"                                                     | 报数字和权衡，不用"仅能 / 仅仅"                   |
| "起初尝试 Transformer 失败，随后改用 CNN 也失败，最终 …"                   | "本文采用混合编码器（3.2 节）；附录 B 报告评估过的备选方案。"                                            | 过程编年移出实验结果（`CF-LOSS-FRAME`）           |
| 结论收尾："然而，该框架无法处理帧率可变的输入。"                           | "… 尚不支持帧率可变的输入；将缓冲机制扩展到异步输入是下一步工作。"                                       | 以方向收尾，保留判定                              |

## 自查（改完后回答四个问题）

1. 每个贡献段的首句是不是主张？
2. 每条限制是否都在它限定的主张之后，且只出现一次？
3. 每个"遗憾的是 / 仅仅 / 仅能 / 未能 / 效果有限 / 存在严重不足"是否都换成了测量值或肯定式范围？
4. 结论末段最后一条限制之后是否加了方向，而不是新的自我否定？

若回答任一问题时删除了对比、结果或 caveat，撤销该修改。

## 与结论章模块的关系

`conclusion` 模块的 `CC-OUTLOOK-TRANS` 要求展望前有承接句（"上述不足有待后续工作 …"），`CF-CLOSE-NEG` 要求负面判定后有方向。两者同时满足的写法：负面判定 → 承接句 → 展望；`references/writing/conclusion-guide-zh.md` 的展望段模板已符合。不要为满足 claim-forward 把结论末段的限制删掉——那会同时触发结论章指南的"限制缺失"。

## 与过度声明防线的关系

过度声明防线向下校准（证据弱于措辞）。claim-forward 向上校准（措辞弱于证据）。两者共用同一阶梯：claim-forward 改写只能把动词抬到证据已支撑的那一级，防线的"反向校准"清单列出了强表达被认可的情形。拿不准时，动词不动，只改顺序。

## 防御性说明的三类处置（仅 LLM）

这三类只由 LLM 判断。不新增观察码，不建词表，也不删除不利结果。强度上限仍见上文与过度声明防线的关系。未验证的弱点不得写成设计优点。

### 保留真实证据边界

范围：删掉以后，方法合法性或证据层级会被追问。
可保留：本文只报告离线回放窗口内的误差，不把该误差写成闭环控制收益。
不可改：删掉该句，只留“本文降低了控制误差”。

### 否定转为正面陈述

范围：仅当原文已经支持正面说法，才把否定改成正面。区分必须还在。
可保留：归一化阈值用于初筛。硬件限值由部署环境单独给定。
不可改：把“不将归一化阈值等同于硬件限值”改成“归一化阈值保证硬件安全”。

### 弱点写成取舍

范围：仅当稿件已经把它写成真实设计选择，才把弱点写成取舍。
可保留：峰值通道的极值误差大于基线。稿件已写明该通道在均方误差下输出分组均值，极值保真不是本设计的目标。
不可改：峰值被低估，因而写成“有效抑制数值抖动并保持单调”。未验证的弱点不得写成设计优点。误检率高于基线必须留下，不得删除，也不得写成“因此更保真”。

### 比喻词只是语境例子

门禁、筑牢、本质安全、理论性能上界不是禁词正则。上下文若已经写明校验、阻断或回退，就按那个可观察机制写。不得据此编制禁用词表。

## 预设反驳与让步壳的四类处置（仅 LLM）

这四类只由 LLM 按语境判断。不新增观察码，不建词表，也不写正则；下文的句式只是语境例子，同样的说法在别的语境里可能合理。上文三类处置保持不变。

其中两类的方向与本指南其余内容相反。"让步后否定"与"断言与让步壳共现"处理的是措辞**强于**证据，属过度声明防线的向下校准。按"去掉防御表述"的直觉删掉让步句，剩下的断言反而更强。因此四类都受以下三条约束：

- 让步句指向稿件中真实存在的差异或混杂时，不得删除让步句。
- 改后文本的断言强度不高于原文。四类处置都不授权抬高未经证据支撑的断言，也不授权删除限制、不利对比或非主线结果。
- 不得补造对照、分层、显著性检验、局限或数字。稿件没有可写的内容时标【待补证】。

### 预设反驳壳

范围：句子回应的异议在稿件数据和所引文献中都找不到来源，且回应本身没有带来证据、条件或范围。常见形态如"这并不意味着 …""不能简单地认为 …""当然，有人可能认为 …"。壳里若含条件、范围或证据，它就是真实边界，按上文"保留真实证据边界"处理。
去向：存在真实混杂或备选解释时，改写为一条带原因的具体边界；没有真实异议时删去壳，保留主张，主张的动词不动；属于定义性区分时保留，按上文"否定转为正面陈述"处理。
可保留：本文所称"响应时间"指从提交请求到返回首条结果的间隔，不包括排队等待时间。（定义性区分）
不可改：删壳的同时把"本文方法缩短了响应时间"改成"本文方法显著优化了系统性能"；把"问卷不能说明受访者的实际使用频率"当作壳删掉——这句是证据边界。

### 让步后否定

范围：让步从句指向稿件中真实存在的差异或混杂（分母变化、样本构成变化、测量口径变化），主句不给分析就否定其影响。常见形态如"虽然 X 有所变化，但这并不影响 … 的判断"。它是过度声称，不是自我削弱。
去向：不得删除让步句。稿件已有分析（分层、调整、共同样本比较）时，把结论绑定到该分析并写出位置；没有分析时把结论收回到数据支持的范围，或标【待补证】。计数与比例、分母变化转交 `experiment --results-analysis` 与 `results-analysis-guide-zh.md` 核对。
可保留：社区随访登记人数由 160 增至 200，完成随访人数由 128 增至 150，随访完成率由 80.0% 降至 75.0%。新增 40 人均来自新划入的两个小区；按小区分层后，原有小区的完成率仍为 80.0%（128/160），新划入小区为 55.0%（22/40），总体完成率下降来自登记构成的变化（表 5-3）。（让步已由稿件中的分层分析回答）
不可改：删掉"虽然登记人数有变化"，只留"新随访方案提高了随访依从性"；补写原文没有的"经分层检验差异不显著"。

### 断言与让步壳共现

范围：同一段内既有高于证据等级的动词（"充分证明""决定因素"），又有模糊让步（"当然不能一概而论，但总体而言在一定程度上 …"）。
去向：按"五步改写"之后的修复顺序处理：证据前置，按确定性阶梯校准断言，再把模糊让步换成一条带原因的具体边界。整段只输出一条 finding。
可保留：14 名受访教师中有 9 名把"缺少示范课例"列为主要障碍（表 4-1）。受访者均来自同一区县，结果反映的是受访教师的自述，不说明各障碍的实际影响大小。（断言已校准，边界带原因）
不可改：只删模糊让步而保留"充分证明"；把断言与让步拆成两条 finding 重复计数。

### 空泛谦辞

范围：限制句既没有对象，也没有条件或量值（"仍存在一定不足""仍有提升空间""具有一定参考价值"），且不是结论章已写出具体局限的承接句。
去向：从稿件补出对象与条件或量值；稿件没有可写内容时标【待补证】，不替作者编局限；与已有限制重复时删副本，保留写在证据讨论处或"本文的不足"小节的那一份。
可保留：结论章展望前写出具体局限的承接句，如"所提方法在更复杂工况下的泛化能力仍存在一定不足"。它满足 `CC-OUTLOOK-TRANS` 要求的"不足 → 承接句 → 展望"，保持不动。
不可改：删掉唯一一处限制；替作者写出稿件没有的局限（如"样本量偏小"）；把"仍有提升空间"改成"已达到最优"。

### 去重

- 清嗓子引导语（"值得注意的是""需要强调的是"）仍归 `deai`。同一句同时含引导语和预设反驳壳时，`deai` 只报引导语，壳的处置在 claim-forward 输出。
- 主张句已由脚本报 `CF-HEDGE-STACK`、同时又构成让步壳时，合并为一条：以壳的处置为主，hedge 计数作佐证。
- 同一证据缺口只输出一条 finding。断言与让步壳共现算一条，不拆成过度声称与让步壳两条。
- 多个具体机制堆叠、末尾统一撤回（"可能是 A，也可能是 B，现有数据无法验证"）仍归 `deai` 的防御性推测解释，本节不重复报告。

准确清楚的原文保留。零发现是合法结果，不为凑数量输出 finding；稿件里未知的内容不得写成确定。
