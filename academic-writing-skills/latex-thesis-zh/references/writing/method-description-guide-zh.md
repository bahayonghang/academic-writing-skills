# 方法模块描述与接口指南

本指南用于中文工科学位论文的方法章，尤其适合包含串行、并行、监督或反馈关系的多模块方法链。
它负责模块级叙述契约；章级骨架读
[`method-chapter-guide-zh.md`](method-chapter-guide-zh.md)，段落连贯性读
[`logic-coherence.md`](logic-coherence.md)，全文主线读
[`thesis-writing-guide.md`](thesis-writing-guide.md)。

先运行候选检查，再按本指南做语义复核：

```bash
uv run python $SKILL_DIR/scripts/analyze_logic.py document.tex --method-narrative --section 〈章名〉
```

`--section` 每次只选择一个章。脚本结果均为候选，`Meaning-Check: NEEDS-LLM` 表示仍需结合
论文事实、公式和实验设计判断。

## 一、完成标准与规则等级

读者无需反推作者意图即可回答以下五问时，方法描述才闭合：

1. 当前模块处理哪项尚未解决的约束？
2. 所选结构或算子的机制为何适合该约束？
3. 数据、状态或监督信号如何从输入变为输出？
4. 设计收益由定义、机制还是实验证据支持？
5. 输出如何进入下一模块，或留下什么约束交给下一模块？

| 规则等级 | 缺失后的影响 | 审阅映射 |
| --- | --- | --- |
| 必须 | 方法契约不闭合、不可复现或模块关系可能被误读 | Major |
| 应当 | 不一定改变事实，但显著增加理解成本 | Minor（推荐修复） |
| 可以 | 取决于方法规模、学科惯例或导师要求 | Info |

## 二、先给总体数据流

多模块方法节先说明共同输入、各模块输出、执行顺序、训练与推理差异，以及最终输出由哪个模块
产生，再进入局部公式。正文、框架图、公式和伪代码必须表达同一条数据流。

```text
问题与数据契约
  -> 总体数据流和模块分工
  -> 模块 A：解决基础约束
  -> 模块 B：处理 A 的输出或剩余约束
  -> 模块 C：完成融合、校准、决策或监督
  -> 训练/推理流程与最终输出
  -> 实验验证对象
```

完成标准：只读总体介绍，即可画出模块节点和有方向的接口边，并指出训练期与推理期的差异。

## 三、单模块六角色契约

每个核心模块覆盖六个角色。角色可以合并成自然段，不需要套用固定句式。

| 角色 | 必答内容 | 核对问题 |
| --- | --- | --- |
| 当前约束 | 上游结果仍缺什么，或原始数据具有什么性质 | 为什么不能直接进入下一步？ |
| 所需能力 | 为消除约束，算子需要具备什么能力 | 需要对齐、筛选、融合、校准还是反馈？ |
| 设计选择 | 所选机制如何提供该能力 | 为什么是该结构或算子？ |
| 处理过程 | 输入经过哪些关键变换 | 计算顺序、对象变化和状态更新是什么？ |
| 输出对象 | 模块准确产出什么 | 名称、形状、语义和有效范围是什么？ |
| 下游接口 | 输出如何被下一模块使用，或还剩什么约束 | 两个模块通过什么关系连接？ |

可用以下骨架检查角色是否齐全，再改写成符合论文语境的自然叙述：

```text
由于〈当前输入/上游输出〉仍存在〈约束〉，后续〈任务〉不能直接进行。
为获得〈所需能力〉，本节采用〈设计〉；其中〈机制〉使其能够〈机制级作用〉。
给定〈输入〉，模型依次执行〈关键变换〉并得到〈输出〉。
该输出作为〈下一模块的输入/监督/约束〉；但〈剩余问题〉仍需由下一模块处理。
```

标准方法说明“如何用于本问题”和相对标准版本的修改即可。可能引起质疑的选择需要给出最低
必要论证：目的、适用性和可核验依据。

## 四、逐边填写接口

每对相邻模块必须写清上游产出、连接变换和下游用途。重构前先填写接口表：

| 上游模块 | 上游产出 | 连接类型 | 中间变换 | 下游模块如何使用 |
| --- | --- | --- | --- | --- |
| A | `z_A` | 串行数据 | 对齐/投影 | B 的直接输入 |
| B | 候选集合 | 校准/选择 | 阈值与预算筛选 | C 的监督样本 |

| 连接类型 | 判据 | 表述重点 |
| --- | --- | --- |
| 串行数据连接 | A 的输出直接成为 B 的输入 | 名称、形状、语义保持还是改变 |
| 并行表征连接 | A、B 共享输入并分别提取表征 | 在何处、按什么规则融合 |
| 监督/目标连接 | A 产生标签、区间、权重、损失或约束 | 信号如何进入 B 的目标函数 |
| 校准/选择连接 | A 产生候选，B 决定准入或排序 | 候选与训练样本、最终输出的边界 |
| 反馈/控制连接 | 下游评价返回上游更新 | 反馈量、更新对象和停止条件 |
| 剩余约束连接 | A 解决部分问题，同时暴露新限制 | 用限制引出 B，形成递进原因 |

没有直接数据依赖时，执行 M-NONDIRECT：主动排除最可能的错误解释。

```text
B 不使用 A 的预测结果作为条件；二者共享同一输入语义，并通过 C 构造的监督关系相接。
```

完成标准：接口表的每一行都能在正文、图或伪代码中找到同义证据，且不会把候选、监督对象和
最终输出混为一谈。

## 五、让公式进入论证

关键公式形成“目的 -> 公式 -> 解释 -> 下游用途”闭环：

```text
公式前：说明为什么需要该计算、输入对象是什么
公式：给出变换、目标或约束
公式后：解释新符号、输出语义及其下游用途
```

- 张量、集合、时间窗口、掩码和标签首次出现时给出外部语义；内部转置或投影另行说明。
- 公式顺序与实际计算顺序一致；为推导而改序时明确说明。
- “式中”只完成符号释义，后文还要说明公式解决的约束、产生的对象和下游消费者。
- 总体图负责全局数据流，模块图负责局部变换；正文引用关键边，而不只写“如图所示”。
- 伪代码的输入、更新/冻结对象、循环顺序、停止条件和输出与正文一致。

## 六、按证据强度陈述收益

| 主张类型 | 所需证据 | 合规示例 |
| --- | --- | --- |
| 定义事实 | 公式或算法定义 | “掩码为零时，条件分支不参与融合。” |
| 机制级作用 | 结构、复杂度或逻辑推导 | “该回退路径保持条件缺失时的数据流闭合。” |
| 经验性能 | 实验、消融或可靠引用 | “该模块提高预测精度。” |
| 因果归因 | 区分性实验或理论证明 | “性能提升主要来自该模块。” |

先分类主张，再按 [`over-claim-guard.md`](over-claim-guard.md) 校准措辞强度。“有利于”“增强”
“提高”“有效解决”不能替代证据；只有设计依据时，使用“用于”“使得”“在定义上保证”或
“为后续……提供”。证据无法区分多个机制时，保留观察事实并将机制标为未确定。

## 七、标题负责导航

独立技术单元可以保留 `\subsection`、`\subsubsection` 或 `\paragraph`。标题只负责导航，
被禁的是用“本模块主要用于……”式报幕替代因果与接口衔接，而不是行内小标题本身。

以下用法属于合法边界，不因标题形式单独触发问题：

- 英文或 Typst 的 Related Work 用行内标题分组方法类别；
- Typst 实验分析段用强调标题引出一组观察；
- 中文实验节使用 `\paragraph{核心结论概括}` 汇总结果。

当一个“模块”只有一两句定义、没有独立输入输出或推导时，将其并入相邻自然段。

## 八、正反例

### 不合格：标题报幕

```text
动态编码模块。本模块用于提取动态特征。
扩散模块。本模块用于生成样本。
筛选模块。本模块用于筛选高质量样本。
```

只有职责清单，没有问题来源、设计理由、输入输出和模块连接。

### 基础合格：有数据流但缺递进原因

```text
A 输出动态特征，B 以该特征为条件生成候选，C 对候选进行筛选。
```

句子说明了顺序，但没有解释为何需要 B、候选为何不能直接使用，以及 C 的准入依据。

### 推荐：约束驱动的连续叙述

```text
A 得到的基础表征仍受原始样本覆盖范围限制，不能补充稀疏区域。为扩展该区域的候选支撑，
B 复用相同输入语义，并以 A 之外的指定条件生成候选。生成条件不等同于可信监督，因此候选
不能直接进入学生训练。C 随后利用独立校准对象将候选转换为带区间和权重的监督样本，最终
由学生模型输出任务结果。
```

相邻模块由剩余约束和监督接口连接，同时排除了错误的数据依赖解释。

## 九、审阅与改写流程

1. 锁定事实边界：保护符号、公式、引用、数值、数据划分和已有实验结论。
2. 画出模块图：为每个节点填写输入、处理、输出、训练状态和失败/回退路径。
3. 填写相邻模块接口表：逐边确定连接类型、变换和下游用途。
4. 先重写总体数据流和模块过渡，再整理模块内部句子，最后调整标题。
5. 逐式检查“目的 -> 公式 -> 解释 -> 下游用途”是否闭合。
6. 将收益按定义事实、机制作用、经验性能、因果归因分级，删除证据越界。
7. 只读每个模块的首段和末段；能够复述整条方法链及每条接口边时结束。

| M-SEQWORD | Script 候选 + LLM 复核 | 小节首句只说明排版顺序，未给因果或约束 | Info/P3 | 四、七 |

## 十一、可复现信息与来源

方法描述至少交代输入来源与时间语义、预处理和数据划分、关键参数的确定方式、训练顺序、
更新/冻结对象、随机过程、停止条件、失败/回退路径，以及输出类型、范围、单位和消费者。
标准方法可以引用原始来源，新增或变体必须展开说明。

- Gopen and Swan, [The Science of Scientific Writing](https://www.americanscientist.org/blog/the-long-view/the-science-of-scientific-writing)：用 topic position 承接旧信息，用 stress position 放置新信息。
- MIT EECS Communication Lab, [Paper: Methods (EE)](https://mitcommlab.mit.edu/eecs/commkit/journal-article-methods-ee/)：方法选择需要最低必要论证，小标题建立逻辑流但不替代衔接。
- MIT MechE Communication Lab, [Journal Article: Methods](https://mitcommlab.mit.edu/meche/commkit/journal-article-methods/)：重点说明如何以及为何将方法用于当前问题。
- IEEE Author Center, [Structure Your Article](https://journals.ieeeauthorcenter.ieee.org/create-your-ieee-journal-article/create-the-text-of-your-article/structure-your-article/)：方法细节应支持复现、信任和扩展。
- Nature, [Formatting Guide](https://www.nature.com/nature/for-authors/formatting-guide)：方法保持简洁，同时包含解释和复现所需信息。
- PLOS ONE, [Submission Guidelines](https://journals.plos.org/plosone/s/submission-guidelines)：统计与分析方法应给出软件、预处理和缺失数据处理等技术细节。
